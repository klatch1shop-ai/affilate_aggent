# Rozetka XML FAQ — відповіді на практичні питання
# Джерело: консультація з документацією, 2026-06-07

## categoryId формат
- В <offer> тег <categoryId> посилається на id з секції <categories> того ж XML
- В <category> атрибут rz_id = числовий ідентифікатор Розетки (пріоритетний над назвою)
- Ми використовуємо rz_id і як id і в categoryId — це правильно
- Не змінювати id категорій після завантаження товарів!

## vendor — обов'язковий
- <vendor> обов'язковий для кожного офера
- Якщо немає бренду — писати "Без бренду" (не залишати порожнім)
- vendor повинен збігатись з брендом в назві товару
- Заборонено: назва магазину, URL, телефон, видозмінені бренди

## picture — вимоги
- Мінімум 1, максимум 15 фото на офер
- Мін розмір: 400x400 px, оптимально 1000x1000 px
- Макс розмір файлу: 10 МБ
- Формати: JPEG, PNG, WebP, GIF
- URL обов'язково HTTPS, без кирилиці, макс 1999 символів
- 403 Forbidden = товар відхиляється, Розетка фізично завантажує фото
- Код помилки: error_load_image (3003)
- Додати IP Розетки в білий список: 89.184.81.192/27 та 89.184.81.128/26

## description_ua — необов'язковий
- Якщо немає — автоматичний переклад з <description>
- Рекомендується заповнювати для якості

## stock_quantity — реальна кількість
- НЕ просто 1 для "є в наявності"
- Розетка автоматично віднімає при кожному замовленні
- При досягненні 0 — товар зникає з продажу
- Якщо дропшипінг — ставити реальну кількість або велике число (99)
- Відсутній або 0 = немає в наявності

## Де знайти rz_id категорій
1. API: GET https://api.seller.rozetka.com.ua/market-categories/search
2. Кабінет: Управління товарами → Довідники → завантажити Excel
3. PriceCreator: Категорії та товари → Додати категорію
4. Ручний: URL сторінки категорії на rozetka.com.ua містить id

## Один XML — кілька категорій
- Так, можна мішати будь-які категорії в одному XML
- Рекомендується не змішувати суттєво різні товари в одній категорії

## Стоп-категорії Розетки
- Блендери і Мультипечі НЕ є стоп-категоріями (наш валідатор помилявся — це стоп-бренди)
- Справжні стоп: зброя, наркотики, алкоголь, тютюн, товари з РФ/Білорусі, підробки
- Дропшипінг заборонений з 2020 (але XML-дропшипери працюють через стоки)

## Критичні vs попередження (валідатор)
КРИТИЧНІ (файл відхиляється):
- Некоректний XML синтаксис
- Неправильне кодування (не UTF-8)
- Відсутні обов'язкові контейнери
- Спецсимволи без екранування (&amp; &lt; &gt;)
- Зміна id після завантаження

КОНТЕНТ (товар відхиляється модерацією):
- Менше 3 характеристик
- Фото на кольоровому фоні або з вотермаркою
- Відсутній vendor
- 403/404 фото

ПОПЕРЕДЖЕННЯ (файл приймається):
- Відсутній name_ua / description_ua
- Аномальна ціна (зріст >3x або падіння >2x) → ручне підтвердження
- Відсутні габарити/вага

## Фото 403 — наслідки
- Валідатор позначає як помилку
- Модератори відхиляють товар
- API код: error_load_image (3003) або error_image_validation (3001)
- Рішення: відкрити публічний доступ або додати IP Розетки в білий список

## Ліміти XML файлу
- Опис товару: макс 50 000 символів
- Назва товару: макс 255 символів
- Значення характеристики: макс 500 символів
- URL фото: макс 1999 символів
- Загальний розмір файлу: не обмежений явно

## Терміни обробки після завантаження
- Ціна і залишки: оновлюються одразу після синхронізації (щогодини)
- Контент (назва, фото, опис): потрапляє на модерацію
- Нові продавці: первинна модерація 7-14 робочих днів
- GitHub raw URL: підтримується, оновлення щогодини автоматично

## Активація посилання
- Кожне нове посилання активується менеджером вручну
- Після активації — автоматичне оновлення щогодини
- Зміна URL посилання = нова активація менеджером

## GitHub як хостинг XML
- Так, raw.githubusercontent.com підтримується
- Репозиторій має бути публічним
- Ціни і залишки = автоматично щогодини
- Контент (назви, фото) = модерація
- Не змінювати id товарів і категорій!
