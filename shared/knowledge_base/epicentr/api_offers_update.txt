		Інструкція для роботи з ендпоінтами API оновлення цін та наявності

	Робота з API передбачає наявність у вашому штаті технічного спеціаліста, який виконає інтеграцію. Обов'язково надайте йому посилання на Swagger із детальним описом методів.

		Як це працює? 

		Замість того щоб заходити в кабінет і вручну змінювати ціну або наявність кожного товару окремо, можна сформувати список необхідних змін і надіслати його одним запитом.

	Важливо!

• В одному запиті можна передати від 1 до 1000 змін.

• Якщо необхідно оновити більше ніж 1000 товарів, зміни потрібно розділити на окремі переліки по 1000 записів та надсилати їх окремими запитами.

• Не потрібно передавати товари, для яких змін цін або наявності не було. Такі записи не потребують оновлення та можуть затримувати обробку коректних змін.

• Не перевищуйте ліміт запитів: не більше 120 запитів за 120 секунд.

	Оновлення товарів відбувається асинхронно, тобто не застосовується миттєво. Система спочатку приймає список змін, перевіряє кожен запис і передає коректні зміни в чергу на обробку. Тому одразу після надсилання запиту ціни або наявність можуть ще не бути оновлені.

Загальний процес:

• Сформуйте список змін — від 1 до 1000 — і надішліть його на ендпоінт: https://merchant-api.epicentrm.com.ua/v1/offers

• Система перевірить кожен запис у списку та передасть коректні зміни в чергу на обробку.

• У відповідь ви одразу отримаєте requestId — ідентифікатор задачі для цього запиту.

• За отриманим requestId можна перевірити результат обробки кожної зміни через ендпоінт: https://merchant-api.epicentrm.com.ua/v1/offers/update-results/{requestId}

	 Зверніть увагу!

На оновлення приймаються лише коректні значення, які відрізняються від актуальних.
Якщо передане значення збігається зі значенням, яке збережене в товарі, така зміна не потребує оновлення та пропускається.
Помилкові значення не опрацьовуються та позначаються як помилкові. Інші записи зі списку при цьому продовжують оброблятися.

	Дублювання товарів у межах одного списку

Якщо в одному списку декілька разів передано зміни для одного й того самого товару, буде опрацьована лише остання зміна. Усі попередні зміни для цього товару будуть пропущені.

		Оновлення цін та наявності товарів 

		METHOD  POST 

https://merchant-api.epicentrm.com.ua/v1/offers

Ідентифікація товару

Оновити товар можна за одним із двох ідентифікаторів:

productId — ідентифікатор товару в системі Епіцентр Маркетплейс;

sku — артикул товару.

Якщо в одному записі передані одночасно productId та sku, товар буде оновлено за productId, а значення sku буде проігноровано.

Якщо ідентифікатор помилковий, тобто товар із таким productId або sku не знайдено у вашій компанії, відповідна зміна не буде опрацьована та буде позначена як помилкова.

Обов'язкові параметри

Для оновлення товару обов’язково необхідно передати:

• ідентифікатор товару — productId або sku;

• ціну та/або наявність товару — хоча б одне з цих значень.

Якщо використовується sku, у нього необхідно передавати значення з поля «Артикул».

	Значення в полі sku має повністю збігатися зі значенням поля «Артикул» в особистому кабінеті.

	Правила роботи з ціною

Ціна має бути більшою за нуль.
Допускається ціле число або число з округленням до 2 знаків після коми.
Стару ціну не можна передати без одночасного оновлення ціни. Значення oldPrice без price у запиті не приймається.
Стара ціна обов'язково має бути більшою за нову ціну.
Якщо передати значення старої ціни, ідентичне новій ціні, ціна оновиться, а стара ціна буде видалена з товару.
Якщо разом зі значенням наявності передати ціну, яка є вищою за збережену в товарі стару ціну, ціна оновиться, а стара ціна буде видалена.
Оновлення ціни недоступне, якщо товар наразі бере участь в акції. У такому випадку буде відповідна помилка:
batch_update.price.product_in_promotion
Правила роботи з наявністю

Поле наявності приймає лише одне з трьох значень:
Значення                                                                                                  Опис
in_stock                                                                                                      Товар в наявності
under_the_order                                                                                      Товар під замовлення
not_available                                                                                            Товару немає в наявності
Будь-яке інше значення вважається некоректним, і відповідна зміна не опрацьовується.

	Відповідь на запит містить:

• кількість отриманих записів у списку (total);

• масив запитаних змін по товарах із деталізацією статусу кожної позиції (items);

• ідентифікатор задачі на оновлення (requestId), який використовується для перевірки результату.

		Перевірка статусу оновлення 

		METHOD  GET 
https://merchant-api.epicentrm.com.ua/v1/offers/update-results/{requestId}
Оскільки оновлення обробляється асинхронно, одразу після надсилання списку не всі зміни можуть бути застосовані. Ендпоінт дозволяє перевірити статус кожної зміни із запитаного списку товарів.

Що важливо знати
Результати доступні лише для задач, створених протягом останніх 14 діб. Після цього отримати результат за відповідним requestId неможливо.
Запит за неіснуючим або застарілим requestId поверне помилку 404.
Запит за чужим requestId, створеним іншою компанією, поверне помилку 403.
У разі перевищення ліміту запитів на хвилину повертається помилка 429.

Статус                                                                                                                         Що означає

skipped                                                                                                                        Опрацювання зміни неможливе через дублювання                                                                                                                                                                                                                 ідентифікаторів у списку або  дублювання значень, які вже є                                                                                                                                                                                               актуальними для товару

		Часті Питання

		Нижче ми зібрали питання та відповіді на них, щоб скоріше зорієнтуватися вам по доступному функціоналу.

				Скільки товарів можна оновити за один запит?

				В одному списку можна передати від 1 до 1000 змін.

Якщо необхідно оновити більше ніж 1000 товарів, зміни потрібно розділити на окремі переліки по 1000 записів та надсилати їх окремими запитами.

Не перевищуйте ліміт запитів: не більше 120 запитів за 120 секунд.

				Чому моя зміна отримала статус skipped?

				Це означає, що в межах одного списку був дубльований запит по цьому товару або значення, яке ви намагалися встановити, вже є актуальним для товару.

Якщо один товар передано декілька разів, опрацьовується лише остання зміна, а попередні пропускаються.

				Як довго зберігається результат за requestId?

				Результат доступний протягом 14 діб з моменту створення задачі. Після цього запит за таким requestId поверне помилку 404.

				Чому не оновлюється ціна товару?

				Оновлення ціни може бути недоступним, якщо товар наразі бере участь в акції. У такому випадку повертається помилка:

batch_update.price.product_in_promotion

				Виникла помилка під час оновлення даних. Куди звернутися?

				Якщо під час роботи з API виникла помилка, зверніться до Підтримки за адресою merchant@epicentrk.ua.
