# Довідка Єпіцентру — локальна копія

Знято з https://supportm.epicentrk.ua/ інструментом `tools/epicentr_support_crawl.py`.
117 сторінок. У кожному файлі — вихідний URL, sha256 тексту й дата зняття.
Повторний запуск покаже, які сторінки Єпіцентр змінив («ЗМІНИЛОСЬ із минулого разу»).

## Пастка, яку треба тримати в голові

[importprom.md](importprom.md): «Якщо у вас вже є заповнені картки в статусах "Чернетка",
"На розгляді" або "Наповнення контентом", при **повторному імпорті** категорії та
характеристики будуть втрачені».

Контекст цитати — імпорт **фіду** (YML з Prom), а не цикл експорт-xlsx → імпорт-xlsx.
Для xlsx діє інше правило ([eksporttovariv.md](eksporttovariv.md)): рядки в статусах
«Модерація» та «Опублікований» просто не завантажуються, решта оновлюється точково.

Чому це нас стосується найбільше: **Єпіцентр забирає в нас саме фід**. Тобто повторна
публікація нашого XML поверх карток, які менеджер уже правив, знищить його роботу.
Це окрема причина не знімати заморозку публікації без рішення власника.

## Суперечність між сторінками

[vidpovidinazapytannya.md](vidpovidinazapytannya.md) (рядок 85) стверджує, що в статусі
«Опублікований» можна міняти **лише** ціну й наявність, а решту — тільки через повернення
в «Наповнення контентом». Це спростовують дві новіші сторінки —
[editproduct2.md](editproduct2.md) («Відтепер можна самостійно редагувати опубліковані
товари без їх зняття з сайту») і [shchooznachayutstatusytovaruvkabinetiprodavtsya.md](shchooznachayutstatusytovaruvkabinetiprodavtsya.md)
(«редагувати більшість даних через перемодерацію»).

Приймаємо версію перемодерації, але **не як доведений факт** — перевіряється першою ж
правкою опублікованої картки. До перевірки вважати спірним.
