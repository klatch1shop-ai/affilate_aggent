# Що працює насправді

Живий опис запущеного функціоналу. **Змінив щось — виправ тут же.** Рішення
власника 07.10.2026: без цього логіка розходиться між двома місцями, і
виправлення в одному не доходить в інше (саме так 07.10 виникли три дефекти
поспіль).

Усе нижче **перевірено запуском**, а не читанням коду. Дата аудиту: 07.10.2026.

Цей файл відповідає на «що зараз запущено». На «куди йдемо і що
відкрито» відповідають [напрями](напрями/README.md).

## 4. Замовлення: що станеться з кожним типом

### NOIRE (Rozetka) — повністю автоматично
наявність з бази SexOpt → підтвердження → **ми створюємо ТТН** (контроль
оплати, якщо не оплачено) → наклейка 100×100 → замовлення в CRM постачальника
через браузер → прикріплення ТТН → Telegram.
Участь власника: нуль. **НЕ ЧІПАТИ — працює.**

### TOPTUL (тільки Rozetka) — ТТН робить постачальник
наявність з фіду «Гранд Інструменту» → підтвердження → заявка поштою на
`opt@grandinstrument.ua` → постачальник сам робить накладну → о 21:00 звірка
бере ТТН з листа «Рассылка ТТН» і пише в замовлення (статус 61).
**Ми ТТН не створюємо і постачальнику не надсилаємо.**

Три типи оплати:
| оплата | у заявці | нагадування власнику |
|---|---|---|
| оплачено на Rozetka | «ОПЛАЧЕНО ЗАМОВНИКОМ, БЕЗ ПІСЛЯПЛАТИ» | ні |
| **на рахунок продавця** | «ОПЛАТА НА НАШ РАХУНОК, БЕЗ ПІСЛЯПЛАТИ» | **так, окреме** |
| післяплата | «Наложенным платежом N грн» | ні |
| онлайн ще не надійшла | — чекаємо, не шлемо | ні |

Режим `TOPTUL_SEND_MODE=live`. Код клієнта `000160594`.

### Carvol (Rozetka) — Excel у Telegram
наявність з фіду `carvol.prom.ua` (7375 SKU) → підтвердження → **Excel у
Telegram-чат Carvol** (`CARVOL_TG_CHAT_ID`), не поштою.

Перевірено наживо 07.10 на замовленні 908130063 (450 ₴, післяплата):
```
статус 1 → 26 «обробляється менеджером» → 2 «підтверджено» → Excel у Telegram
```
**Статус міняється через проміжний 26**: перехід 1 → 2 недоступний, агент
спершу ставить 26 і лише звідти підтверджує. Небезпечні переходи (40, 49)
заблоковані явно.

ТТН для Carvol ми НЕ створюємо — приходить окремо.

У позиціях замовлення Rozetka **немає поля артикула** — лише `item_id` і
назва; артикул буває в дужках у кінці назви (`… (RZ-VW08)`).

### Єпіцентр (NOIRE) — повністю автоматично
лише `provider=nova_poshta`; `cvz_epicentr` не чіпаємо. Підтвердження → ТТН →
номер у замовлення (`PATCH /v1/oms/orders/{id}/shipment-number`) → CRM
постачальника → Telegram. Статуси не вгадуємо — питаємо `allowed-statuses`.

### NOIRE на Prom — ланцюг готовий, у розклад НЕ поставлений
`tools/prom_order_pipeline.py` — той самий ланцюг, що на Rozetka: наявність →
ТТН → наклейка → CRM постачальника → прикріплення → Telegram.

ТТН записується в замовлення автоматично:
`POST /delivery/save_declaration_id {delivery_type, order_id, declaration_id}`
(`nova_poshta | ukrposhta | meest | rozetka_delivery`). Якщо запис не вдався —
власнику приходить попередження, мовчки не губиться.

Живої перевірки ще не було — замовлень на Prom немає з 09.09. У cron не
ставимо, доки не проженемо перше замовлення при власнику.

**Старий агент Prom зупинено 07.10.** Він жив у системній службі root
`order-agent.service` з `Restart=always` (тому й піднімався після кожного
kill), був написаний під дропшипінг TOPTUL, якого на Prom немає, і тиждень
працював із мертвим токеном. Зупинено і вимкнено.

### dropoffice — **АВТОМАТИЗАЦІЇ НЕМАЄ**
фід синхронізується щогодини, замовлення обробляються вручну.

## 5. Помічник у Telegram

Нижня панель: `🆕 Нові замовлення` · `📦 Стан фідів` · `🖥 Статус системи` ·
`❓ Довідка` · `🤖 СУПЕРБОТ`

**Другий канал: `VSCODE <текст>`** — повідомлення лягає у скриньку
`data/vscode_inbox.jsonl`, яку Claude читає під час роботи. Бот нічого не
виконує, лише приймає.

### Команди режиму «СУПЕРБОТ»
| фраза | ризик | дія |
|---|---|---|
| `замовлення` / `замовлення <номер>` | R0 | замовлення Prom |
| `питання` | R0 | чати покупців Prom |
| `відповідь <гілка> <текст>` | R2 | відповісти покупцю |
| `статус <номер> отримано` | R2 | лише received/delivered/paid |
| `наявність <артикул> немає` · `кількість <артикул> 7` | R2 | залишки Prom **одразу**, без фіду |
| `ттн <номер>` | R3 | накладна за замовленням |
| `накладна Прізвище; Імʼя; телефон; місто; відділення; сума[; післяплата]` | R3 | накладна руками |
| `епіцентр` · `епіцентр <номер>` | R0/R3 | замовлення Єпіцентру |
| `вихід` | — | вийти з режиму |

R0 виконується одразу. R2 і R3 — лише після кнопки «Виконати»; пропозиція
живе 10 хв (R2) і 5 хв (R3).
