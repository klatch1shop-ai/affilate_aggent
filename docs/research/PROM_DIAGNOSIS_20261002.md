# Prom: повна діагностика, 02.10.2026

Зібрано за ніч на вимогу власника: спершу всі можливі способи дізнатись
правду, потім усе, що ними вдалось зібрати. Усі числа — заміри, не оцінки.

## 1. Скільки насправді продано

Джерело: API кабінету Prom `/orders/list` — незалежне від нашої бази.

**16 замовлень за весь час. 6 доставлено, 10 скасовано.**

| рік-місяць | замовлень |
|---|---|
| 2025-06 … 2025-12 | 10 |
| 2026-04 | 3 |
| 2026-05 | 2 |
| 2026-09 | 1 |

У нашій таблиці `orders` було 14 записів, з них 13 датовані одним днем
16.05.2026 — це разовий імпорт історії при налаштуванні системи (два записи
по 1 грн, три однакові по 590 грн в одне село), а не продажі.

### Причини скасувань — головне відкриття

| причина | разів |
|---|---|
| Довго відправляли замовлення | 2 |
| Зі мною не звʼязались | 2 |
| Товар не потрібен | 2 |
| Немає в наявності | 1 |
| Немає різновиду товару | 1 |
| Інше / без причини | 2 |

**Чотири з десяти скасувань — наша провина в обслуговуванні**, не пошук і не
картки. У 2025 році з перших девʼяти замовлень сім скасовано.

Гіпотеза, яку це породжує: погана обробка замовлень 2025 → висока частка
скасувань → пониження магазину в ранжуванні Prom → майже нульова видимість
із 2026. Не доведено, але пояснює послідовність подій краще за ключі.

## 2. Що ТОЧНО не є причиною (перевірено й відкинуто)

| гіпотеза | перевірка | результат |
|---|---|---|
| товари позначені оптовими, їх ховає роздрібний фільтр | `selling_type` усіх 5660 товарів | **усі `retail`** — спростовано |
| немає категорії порталу | `category` кожного товару | **0 без категорії**, 50 категорій, усі профільні |
| товари не на вітрині | `status` | **усі 5660 `on_display`** |
| оптові ціни або мінімальне замовлення ховають товар | `prices`, `minimum_order_quantity` | порожні в усіх |
| ключові слова не індексуються | маркер-експеримент 15-18.09 | **спростовано, див. §3** |

## 3. Ключі індексуються — це доведено

Маркер-експеримент 15.09: вигадані слова «зорвінтал» (поле `keywords_ua`,
50 карток) і «квербаліс» (поле `keywords`, 50 карток), яких немає ні в назві,
ні в описі, ні деінде на Prom (відʼємний контроль до старту — 0 результатів).

Після нічного імпорту обидва маркери знайдено **в основному блоці видачі**,
в українському і російському пошуку.

**Але знайдено 8 карток із 50 і 7 із 50.** Перелік знайдених **однаковий у
трьох замірах поспіль** (16.09 03:02, 16.09 05:48, 18.09 05:50), нуль
ротації. За критерієм, записаним в інструменті ДО заміру, стабільний перелік
означає **поріг потрапляння у видачу**, а змінний — ротацію. Отже поріг.

Наслідок: з нашого магазину на один запит випливає 8-9 карток, решта лежить
в індексі й не показується ніколи. Ключ «женские вибраторы» стоїть на 1272
картках — показатись можуть вісім.

### Стан ключів (заміряно на живих даних з API, 02.10)

- 39 795 слотів заповнено з можливих 50 940 → **11 145 порожні**
- **75,8 % карток (4289) не мають жодного унікального ключа**, медіана 0
- 92,9 % слотів — фрази, спільні з іншими нашими ж картками
- 35,4 % слотів — фрази, всі слова яких уже є в назві картки

Поле `keywords_ua` існує і заповнене в усіх 5384 картках фіду. API його не
віддає — тому замір «лише по API» дає хибний висновок «українських ключів
немає». Це моя помилка вранці 02.10, виправлено.

## 4. Знайдена і усунена поломка

Постобробка фіду Prom падала **з 26.09 о 07:41, 28 публікацій поспіль**:
`ModuleNotFoundError: No module named 'pymorphy3'` на сервері. Збій
постобробки не блокує випуск («краще опублікувати коректний фід без
покращень»), тому помилка була мовчазною: тиждень фід виходив без виправлень
назв, ключів і без маркер-експерименту.

Усунено 02.10: встановлено `pymorphy3` і `pymorphy3-dicts-uk`, постобробка
проходить усі кроки.

## 5. Видимість — що саме заміряно

Інструмент `prom_visibility_check.py`, окремий екземпляр браузера на кожен
запит (щоб мовне налаштування не переносилось між запитами через сесію).

| режим запиту | знайдено |
|---|---|
| власний артикул | **0 з 14** |
| точна назва товару | 15-17 % |
| «тип + бренд» з наших ключів | 3 з 148 (2 %) |

Повторний замір 15.09 проти 12.09: значущої зміни немає (МакНемар p = 0,73),
видимість за точною назвою 10-14 %. Мигання: з 21 знайденої хоч раз стабільно
в обох прогонах — лише 12.

**Застереження:** HTML-інструмент бачить лише основний блок видачі. Висновок
«не знайдено» коректніше читати як «не в основному блоці».

## 7. Чого дізнатись НЕ вдалось і чому

| що | чому недоступно |
|---|---|
| статистика пошукових запитів | в API немає (перевірено 21 метод); сторінки пошуку закриті в robots.txt |
| ProSale, платне розміщення, тариф | лише в кабінеті; вхід не автоматизується — віджет у крос-доменному iframe |
| чи понижений магазин у ранжуванні | назовні не видно; це питання до підтримки |
| чи є картка в індексі, якщо не в основному блоці | ззовні не розрізнити індексацію й допуск до показу |

Доступні методи API: `/products/list`, `/groups/list`, `/orders/list`,
`/messages/list`, `/clients/list`, `/delivery_options/list`,
`/payment_options/list`. Аналітичних методів немає.
