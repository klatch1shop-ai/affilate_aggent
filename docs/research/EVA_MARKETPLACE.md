# EVA Маркетплейс: довідка продавця — повний збір і аналіз

**Дата:** 25.09.2026. **Привід:** власник домовився про магазин на EVA (нове досягнення),
дав посилання на довідку — зібрати все й підготуватись до фіду з косметикою.
**Зібрано:** `tools/eva_help_crawl.py`, 11 статей (уся довідка на сьогодні, майданчик новий,
2 з 4 категорій довідки ще порожні), локальні копії — `shared/knowledge_base/eva/sellersupport/`.

## 1. Технічна деталь збору (щоб повторити пізніше)

Сайт — Nuxt SPA на рушії Tawk.to Knowledge Base, у сирому HTML тексту нема. Знайдено чистий
JSON API без потреби в браузері:
- `GET /api/categories?propertyId=654b86dca84dd54dc489e4b1&siteId=primary`
- `GET /api/articles?propertyId=…&siteId=primary&categoryId=<id>` — пагінація курсором `next`
- `GET /article/<slug>` — рендерена сторінка, текст у `__NUXT__`, витягується регуляркою
  без рендерингу браузером (деталі — докстрінг `tools/eva_help_crawl.py`).

## 3. Специфікація фіду (з реального прикладу XML у довідці)

Формат — **YML** (той самий, що ми вже генеруємо для Rozetka/Prom), з відмінностями:

| Вимога | Деталь |
|---|---|
| URL прайсу | **статичний**, не змінюється |
| Кодування | UTF-8 |
| Заборонені символи | ASCII 0–31, крім 9/10/13 (таб, перенос, повернення каретки) |
| Спецсимволи в тексті | `"`, `&`, `<`, `>`, `'` — замінювати на коди (стосується тексту, не тегів) |
| **id товарів і категорій — не можна змінювати** після додавання | те саме правило, що в Rozetka/Prom — треба один раз призначити стабільний id |
| User-Agent для завантаження | `EvaMerchantBot/1.0` (для фото — Mozilla-рядок) |
| **IP EVA для нашого whitelist** | `138.197.179.150`, `164.92.129.224` |
| Обовʼязкові теги офера | `price`, `price_old`, `stock_quantity`, `currencyId`, `categoryId`, `picture` (кілька), `vendor`, `article`, `name`, `name_ua`, `description`/`description_ua` (CDATA), `param` (довільна кількість) |
| Валюти в шапці | курс USD/EUR до UAH прямо у фіді (`<currencies>`) — на відміну від Rozetka, де курс не в самому фіді |

**Порівняння з нашими фідами:** структура майже ідентична Rozetka YML (ми вже вміємо генерувати
такий формат — `content/*`, `sync/epicentr_offers.py` — інший майданчик, інший формат, але
принцип генератора той самий). Головна відмінність — обовʼязкові `name` (рос.) **і** `name_ua`
одночасно, і явний курс валют у шапці.

## 4. Чого ще не знаємо (відкриті питання)

- **Перелік дозволених категорій останнього рівня й стоп-брендів** — у статті `dostupni-katehorii-ta-brendy`
  це посилання на окремі таблиці, які **не вдалося витягти** зі статичного JSON (рендеряться
  окремим компонентом, не текстом статті). Треба відкрити в браузері й забрати вручну, або
  попросити менеджера надіслати файлом — це блокер для оцінки, скільки з наших ~13 000 SKU
  косметики проходить за категоріями.
- **Заборонені товари** — стаття називається в змісту («Заборонені товари для продажу на EVA
  Маркетплейс»), але власного файлу з таким текстом серед 11 зібраних нема (посилання веде на
  ще не опубліковану сторінку — довідка розбудовується).
- **«Окремий фід з косметикою»**, про який казав власник, — чи це фід самого EVA під косметичну
  категорію окремо від загального прайсу, чи наш SMTM-фід косметики (`smtm-content-drive` у
  памʼяті) — уточнити.

## 5. Наступні кроки

1. **Дістати таблицю дозволених категорій і стоп-брендів** (у браузері або через менеджера EVA) —
   без неї не можна порахувати, скільки товарів косметики взагалі проходять.
2. Порахувати, чи набирається **50 SKU** у дозволених категоріях косметики — з наявним каталогом
   SMTM/NOIRE це майже напевно так, але перевірити треба з реальним переліком категорій.
3. Написати генератор YML для EVA за зразком наявних (`content/`, `sync/`) — з `name`+`name_ua`,
   валютною шапкою, стабільними id.
4. Дати статичний URL фіду й **два IP в whitelist на сервері** (`138.197.179.150`, `164.92.129.224`) —
   технічна дія, потрібен дозвіл власника, якщо це стосується firewall на usa1.
5. Перевірити назву магазину за списком заборон (§2) до реєстрації кабінету.
