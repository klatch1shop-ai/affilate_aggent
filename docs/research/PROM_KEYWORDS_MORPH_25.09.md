# Prom: справжня морфологія в шарі 3 генератора ключів — вимірювання й фікс

**Дата:** 25.09.2026. **Привід:** власник — «думаю вирішення там, до вечора»
(про пастку видимості Prom, `prom-indexation-baseline`). Що знайшов і зробив
по коду: `tools/prom_kw_matrix.py`, дослідницький/вимірювальний інструмент
для якості ключів шару 3 (біграми з опису). **Чесно попереджаю нижче (§4):**
цей інструмент **не є** живим генератором фіду — `noire_prom_generator.py`
працює окремо, зі своєю логікою.

## 1. Стан ДО (перевірено, не з памʼяті)

Пам'ять `prom-keywords-code-defect` каже: `_is_adj` (закінчення слова)
плутає прикметник з родовим/місцевим відмінком іменника — 47,9 % карток.
Перевірка коду 25.09 показала: шар **не вимкнений** (коментар у файлі
застарілий) — з 19.09 діє додатковий фільтр `_strict_pair` (тип у називному
+ бренд латиницею), 89 % точності, **859 фраз** на живому фіді (5384 офферів).

## 2. Морфологія: встановлено, виміряно, двічі виправлено себе

`pymorphy3` + `pymorphy3-dicts-uk` (додано в `requirements.txt`). Нова функція
`_adj_noun_agree()`: прикметник **перед** іменником, обидва в називному,
узгоджені в числі й (для однини) роді.

**Перша власна помилка:** `--report` (вбудований інструмент порівняння
старе/нове) порахував «суперечностей із Призначенням: 0 → 1080» —
виявилось, сам `--report` викликав `contradicts(p, purpose)` **без**
аргументу `name`, тоді як реальний фільтр `add()` викликає з ним. Перевірив
на прикладах (SO1640/1641, «кліторальний» у назві, «Призначення: вульва») —
`contradicts(..., name=name)` коректно каже `False` для всіх 1080. Виправив
сам `--report` (tools/prom_kw_matrix.py). Після фіксу: **0 → 0**.

**Друга власна помилка:** `pymorphy3.parse(word)[0]` — це **не** «найімовірніший
розбір», а перший запис словника при однаковому `score`. «Кульки» має
родовий однини й називний множини з **однаковим** score=1.0 — `[0]` випадково
давав родовий, і «вагінальні кульки» (реальна хороша фраза з фіду) відхилялась.
Виправив: `_adj_noun_agree` перевіряє **всі** розбори обох слів, не лише перший.

## 3. Виміряно на живому фіді (5384 офферів), після обох виправлень

| | Було | Стало |
|---|---|---|
| унікальних фраз | 10 070 | 9 954 |
| вживань | 42 066 | 41 535 |
| фраз на товар у середньому | 7,8 | 7,7 |
| **карток із < 4 фраз (мінімум безпеки)** | **97** | **51** |
| суперечностей із «Призначенням» | 0 | 0 |

Головний результат — **97 → 51**: майже вдвічі менше карток нижче безпечного
мінімуму (переважно БДСМ/подарунки/сувеніри — категорії без характеристик,
де опис був єдиним джерелом ключів). Загальна кількість фраз майже не
змінилась (слоти на картку обмежені `MAX_SLOTS`) — це заміна гіршого
наповнення кращим, не наростання обсягу.

## 4. Чесно: це НЕ застосовано до живого фіду

`prom_kw_matrix.py` не викликається з `noire_prom_generator.py` (перевірено
`grep` — нуль збігів). `keywords_ua` у `output/noire_prom.xml` рахує **окрема**
логіка (`_fill`, теги, не морфологія опису). Тому сьогоднішній фікс — це
готовий, виміряний, протестований (10 тестів, `tests/test_prom_kw_agreement.py`)
покращений алгоритм, а не задіяна зміна.

Експериментальний файл із новими ключами, зроблений існуючим A/B-інструментом
(`tools/prom_kw_rebuild.py`, задум 08.09 — міняти рівно одне поле для чистого
експерименту): `/tmp/noire_prom_kw_v2.xml` — **не в git** (55 МБ, дані
товарів), лежить локально на ноутбуці.

## 5. Наступний крок — рішення власника

Два шляхи:
1. **Контрольований експеримент**, як і задумано інструментом: підмінити
   лише `keywords_ua` в кабінеті цим файлом на частині карток, почекати
   нічний імпорт (~01–03 Київ), звірити видимість через кілька днів
   (`tools/prom_search.py`, `tools/prom_dup_test.py`) — саме методологія,
   яку команда вже використовувала 08–19.09.
2. **Вшити в живий генератор** (`noire_prom_generator.py`) — більший обсяг
   роботи, чіпає код, що зараз реально формує фід; сьогодні не робив.

**Я рекомендую (1):** дешевше, оборотне, дає число замість здогаду —
той самий принцип, що вже працював у цьому дослідженні тричі поспіль.
