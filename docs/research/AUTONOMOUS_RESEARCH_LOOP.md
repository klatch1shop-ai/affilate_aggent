# Процес, який сам досліджує, припускає й будує звʼязки — розбір і наш план

**Дата:** 20.09.2026. **Запит власника:** «в майбутньому нам треба буде процес, який досліджує,
робить припущення, знаходить усю інформацію та сам будує звʼязки, воронки».
**Джерела:** два Shorts (розбір Gemini + звірка з розшифровкою), перевірка фактів на GitHub.

## 1. Що в двох відео

### 1.1. TradingAgents — багатоагентна «фірма» (корисне для нас)
Перевірено: [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents) —
**107 632 зірки**, 20 592 форки, Apache-2.0, оновлено 18.09.2026. Стаття arXiv:2412.20138.
У відео сказано «97 000 розробників уже взяли» — **не перебільшення** (Gemini у своєму розборі
помилково назвав це маніпуляцією; звірка показала протилежне).

Архітектура (з відео, 00:14–00:34):
1. **Аналітики** (4 ролі) — фундамент, новини, настрої, графіки.
2. **Дослідники** — «бик» проти «ведмедя»: два агенти **сперечаються** про ту саму ситуацію.
3. **Трейдер** — приймає рішення.
4. **Ризик-команда** — може накласти вето; **портфельний менеджер** підписує.
5. **Пам'ять** — кожне рішення зберігається, порівнюється з фактом і впливає на наступні.

### 1.2. TimesFM — прогноз часових рядів (обмежено корисне)
Перевірено: [google-research/timesfm](https://github.com/google-research/timesfm) — 33 248 зірок,
Apache-2.0. Це **не агент**: він не шукає інформацію й не будує звʼязки, а продовжує числовий ряд
(«GPT для часу»). У відео («передбачить буквально що завгодно») — маркетинг: модель безсила перед
подіями, яких не було в історії.

## 3. Наш процес (пропозиція) — «дослідник товару»

```
1. ПРИВІД        нове питання покупця · падіння продажів · новий фід постачальника · відгук
2. ЗБІР          наші дані: історія замовлень, залишки, ціни, питання й відгуки
                 зовнішні: ціни конкурентів (SKILL-30), пошукові запити майданчика, відео ніші (TASK-19)
3. ПРИПУЩЕННЯ    Gemini формулює 2–3 гіпотези: «чому це сталося» / «що зробити»
4. СПІР          «за» проти «проти» — два прогони з протилежними завданнями, кожен наводить
                 докази з кроку 2; без доказу теза не зараховується
5. РИЗИК-ВЕТО    детерміновані правила: ціна не нижче порогу, наявність невідома ≠ нема,
                 зміст фіду після модерації не чіпаємо, політики соцмереж
6. ПЛАН          конкретна дія з параметрами (ціна, текст, тема ролика, лист постачальнику)
7. ✅ ВЛАСНИК    кнопка підтвердження (механізм TASK-13), з повтором усіх параметрів
8. ВИКОНАННЯ     через наші адаптери, із журналом
9. ЗВІРКА        через 7/14/30 днів: що сталося насправді (продажі, перегляди, відповіді)
                 → оцінка гіпотези → наступний цикл
```

**Воронки** в нашому випадку — це два ланцюжки, які треба зімкнути:
- **товарна**: показ картки → клік → замовлення → викуп → відгук;
- **контентна**: тема (з питання покупця) → ролик → перегляд → перехід → замовлення.

| Потрібно | Стан |

| ціни конкурентів | 🟡 є інструмент, потрібен регулярний збір |
| покази й кліки на маркетплейсах | ❌ **немає** — без них верх воронки сліпий (є лише непряма видимість Prom) |

| прогноз попиту (TimesFM-подібний) | ❌ не потрібен на старті: спершу проста статистика (середнє, тренд, сезон) |
