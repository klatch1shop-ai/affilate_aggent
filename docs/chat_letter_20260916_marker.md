# Маркер-експеримент: ключі індексуються, але видно 7–8 карток із 50 (16.09)

Перевірка за планом, який ви оцінювали 15.09. Дані:
`docs/prom_marker_experiment_log.tsv`, опис і висновки:
`docs/prom_marker_experiment_20260915.md`.

## Результат

100 карток (38 категорій), маркер лише в полі ключів, у назві й описі його
немає. Публікація 15.09 о 19:40, нічний імпорт, перевірка 16.09 о 04:00
браузером (обидва блоки видачі).

| | UA «зорвінтал» (`keywords_ua`) | RU «квербаліс» (`keywords`) |
|---|---|---|
| імпорт підтверджено API | — (укр. ключів API не віддає) | **50/50** |
| пошук ua / ru, 2 прогони кожен | 8/50 в усіх 4 | 7/50 в усіх 4 |
| частковий блок | 0 | 0 |
| усього карток у видачі | 8 | 9 |

Позитивний контроль SO5178 пройдено (без нього скрипт не будує перевірку).
Негативний контроль до старту: обидва слова давали 0. Переліки SKU
однакові в усіх прогонах — мерехтіння немає, хоча на звичайних запитах
мигає 43 % карток.

## Що я з цього роблю (В)

1. **Обидва поля ключів індексуються, і саме в основному блоці.** Мова
   запиту не впливає. Для `keywords_ua` це перший прямий доказ; усі
   попередні «докази нероботи ключів» мали дефект розділеного збігу.
2. **Видно меншість карток.** Для групи RU API доводить наявність слова в
   `keywords` усіх 50 карток, а пошук показує 7. Конкуренції за цим
   запитом немає взагалі. 14–16 % збігається з базовою видимістю за
   точною назвою (9,5–14 %).
3. Отже, крім рангу серед однакових пропозицій (2/178 при ~32) діє
   **другий обмежувач: більшості карток у видачі немає навіть тоді, коли
   конкурувати нема з ким**.

## Гіпотеза, яку не вважаю висновком (П)

Знайдені картки дешевші: медіана 559 грн проти 1339 грн (перестановочний
тест, p = 0,037). Розмір категорії різниці не дає (p = 0,17); статус,
наявність, варіативність однакові. Порівняння **post-hoc**, 15 карток зі
100, кілька ознак одразу — тож це тема для окремого заміру з наперед
заданою гіпотезою, а не результат.

## Питання

1. Чи згодні, що п. 2 сформульовано коректно, і чи не бачите тут
   альтернативного пояснення (наприклад, часткова індексація після імпорту,
   яка дожене за добу)? Повтори 17 і 18.09 заплановані саме на це.
2. Як коректно перевірити гіпотезу ціни, щоб не повторити помилку відбору,
   якої ми припустилися на 10 товарах? Мій план: нова партія карток,
   маркер, дві наперед задані цінові групи по 40 карток, однакові
   категорії в обох групах.
3. Чи ставити п. 2 головним аргументом у листі в підтримку Prom
   (`docs/prom_support_letter_draft_20260915.md`, розділ 2)? Він
   відтворюється одним запитом, тому виглядає сильнішим за статистику по
   однакових пропозиціях.
4. Партію 6 ключових слів, за правилом рішення, роблю з нижчим
   пріоритетом. Чи не варто взагалі відкласти її, поки не зрозуміло,
   чому 86 % карток не потрапляють у видачу?
