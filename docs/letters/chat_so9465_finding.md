## Що НЕ є причиною

Ви припустили механізм 161610: «Prom перепризначає категорію → довідник дає
неправильний тип». **Перевірив — не він.**

```
фід              : 161007 «Бдсм-іграшки»     ✓
кабінет          : 161007 «БДСМ-игрушки»     ✓  (збігається)
довідник RU      : «Бдсм-іграшки» → ['бдсм игрушка', 'f', 'для ролевых игр']  ✓
```

Категорія правильна на всіх трьох рівнях. Довідник дає «бдсм игрушка», а не
страпон.

Слова «страпон» **немає взагалі** ні в параметрах, ні в назві, ні в описі:

```
Матеріал = Метал · Колір = Червоний · Тип аксесуару = ТРУСИКИ
Вібрація = Так · Сумісність з секс-іграшками = Так
name (RU): Кожаные трусики для вибратора Liebe Seele Wine Red Forced Orgasm
```

## Що є причиною — третє джерело категорії

Ключі беруться не з фіду й не з кабінету, а з файлу
`docs/prom_kw_level1_all.json`, і там записано:

```
SO9465:  category = «Страпони»
         final    = ['страпон для пар', 'страпон червоний',
                     'шкіряні трусики для вібратора']
```

**Помилкова категорія записана в самому джерелі ключів.** Далі вона працює
двічі: фрази в `final` уже побудовані навколо страпона, і `_fill()` добирає
теги за тим самим хибним ключем категорії.

Тобто ваша гіпотеза «категоріальна помилка, а не лінгвістична» **правильна**,
але категорія хибна не в Prom і не в фіді, а в **третьому місці**, про яке ми
досі не говорили.

## Наслідок для порядку дій

Ваш пункт 4 — повний RU-аудит — треба ставити **після** цього, і ви це
передбачили. Тепер видно чому конкретно: **349 карток (6.6 %) дадуть
нерелевантні ключі в обох мовах**, і якщо міряти RU до виправлення, ці
картки потраплять у підрахунок як лінгвістичні помилки, хоча вони
категоріальні.

Те саме стосується UA. У моїй розмітці 49 карток типу Р було 9 — треба
перевірити, скільки з них насправді цього класу, а не `head_noun`.

Перевірив — і мушу виправити те, що спершу написав не перевіривши.
**Три з дев'яти карток типу Р мають розбіжність категорії:**

```
SO8145   JSON «Бдсм-іграшки»  / фід «Вібратори»        ✗
SO2964   JSON «Бдсм-іграшки»  / фід «Анальні пробки»   ✗
SO9465   JSON «Страпони»      / фід «Бдсм-іграшки»     ✗
решта 6  збігаються                                    ✓
```

Це змінює атрибуцію: **до третини помилок, які я порахував як тип Р
(`head_noun`), можуть насправді бути дефектом 8 (категорія в JSON)**.
Зокрема `SO2964` — анальна пробка з ключем «класичний вібратор» — має в JSON
категорію «Бдсм-іграшки», і частина її фраз могла прийти звідти, а не з
`head_noun`.

Тобто **два дефекти накладаються**, і розділити їх можна лише після
виправлення категорій: спершу звірити JSON із фідом, тоді переміряти тип Р
на чистих даних. Інакше калібрування `head_noun v2` на 150 картках
успадкує це змішування.
