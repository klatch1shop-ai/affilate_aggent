## 1. Інвентаризація статичних джерел

Конвеєр ключів читає **три** статичні файли. Усі застарілі:

```
docs/prom_category_ru.json      14.08   25 діб      2 КБ
docs/prom_kw_level1_all.json    16.08   23 доби  6155 КБ
docs/prom_name_shorten.json     15.08   23 доби    19 КБ
```

Фід за цей час перезбирався **чотири рази на добу** — приблизно 92 рази.
Жоден із трьох файлів жодного разу не звірявся з ним.

### Покриття кожного — і в двох знайшлись діри

**`prom_kw_level1_all.json`**
```
записів              5481
є у фіді, немає у файлі    61   ← товари без джерела ключів узагалі
є у файлі, немає у фіді   156   ← записи про товари, яких більше немає
```

**`prom_category_ru.json`** — і тут новий дефект того самого класу:
```
категорій у довіднику          30
категорій у фіді               44
категорій фіду БЕЗ запису      14
```

У коді це:
```python
cat = _load_ru_cat().get((category or '').strip())
single, gender, purpose = cat if cat else ('', 'm', '')
```

Категорії немає в довіднику → **рід за замовчуванням «m», без жодної
позначки**. Це той самий патерн «мовчазний відмов», що й дефекти 1-7.

Масштаб: **71 товар (1.3 %)**, найбільше «Жіноча еротична білизна і одяг» — 49.
Невелика цифра, але механізм ідентичний.

**`prom_name_shorten.json`** — 192 записи на 5386 товарів. Це вибірковий
файл за задумом, не покриття; дірою не є.

## 3. Головне застереження до списку (в)

**Звірка показує розбіжність, але НЕ показує, хто з двох правий.** Це різні
питання, і я не можу відповісти на друге автоматично.

Розбір 58 карток на око дає щонайменше три різні ситуації:

**Обидві категорії захищаються — подвійна природа товару**
```
SO8145  «Вібратор з електростимуляцією Mystim»
        JSON «Бдсм-іграшки» / фід «Вібратори»
        це і те, і те — 10 карток Mystim у списку саме такі

SO8298  «Шкіряна портупея Art of Sex»
        JSON «Бдсм-іграшки» / фід «Жіноча еротична білизна»
        теж обидві правильні
```

**Правий фід, JSON помиляється**
```
SO3067  «Стимулятор простати Nexus»
        JSON «Насадки на член» / фід «Масажери простати»  ← фід точніший
```

**Правий JSON, помиляється ФІД**
```
SO6071  «Двостороння маска Doc Johnson»
        JSON «Збуджуючі засоби» / фід «Медичні маски і респіратори»
        ← фід відніс еротичну маску до медичних респіраторів
```

Останній випадок важливий: **дефект може бути й у фіді**, а не лише в
застарілому JSON. Автоматично оновити JSON із фіду означало б у цьому
випадку зіпсувати правильні дані.

**Тому пункт 2 вашого порядку — рішення про виправлення — я б не робив
одноразовим оновленням JSON із фіду.** Це перенесе помилки фіду в джерело
ключів.

## 4. Що з цього випливає для порядку дій

Ваш пункт 2 («одноразово чи постійна звірка») отримує третій варіант:

```
варіант 1  оновити JSON із фіду одноразово     ← перенесе помилки фіду
варіант 2  постійна звірка перед генерацією    ← те саме, тільки регулярно
варіант 3  звірка як ПОПЕРЕДЖЕННЯ, не як виправлення:
           конвеєр падає або позначає товар, коли джерела розходяться,
           і людина вирішує, хто правий
```

**Схиляюсь до третього.** 58 карток — це обсяг, який людина розбирає за
годину, і жоден автомат не відрізнить «подвійна природа» від «хтось
помилився». А от **постійна перевірка, що розбіжностей не більшає** —
автоматизується повністю й ловить наступний дрейф за три тижні.

**F16531** із попереднього листа (засіб для догляду з категорією
«Мастурбатори») у ці 1870 не входить — він в іншій підмножині. Виніс його
окремо як кандидата на негайну ручну перевірку, як ви й пропонували.

Повний список 58 артикулів — у файлі, готовий для ручного розбору.

## 5. Дев'ятий дефект, для повноти обліку

```
9  prom_category_ru.json: 14 категорій із 44 відсутні,
   рід мовчки стає «m» — 71 товар
```

Природа — знову «мовчазний відмов», але цього разу через **неповноту даних**,
а не через логіку. Тобто дефекти 8 і 9 — це два підвиди одного класу:
дані розійшлися (8) і даних бракує (9), і в обох випадках код не помічає.
