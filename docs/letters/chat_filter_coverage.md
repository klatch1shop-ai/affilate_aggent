## 1. Покриття фільтра: ви праві, і навіть більше, ніж припускали

Прогнав обидва фільтри заднім числом по 11 хибних фразах із 9 карток
типу Р у розміченій вибірці.

```
Ф1  «головне слово фрази присутнє в назві цілим словом»   3 з 11 = 27 %
        ← мій запропонований фільтр

Ф2  «означення присутнє в назві або характеристиках»       5 з 11 = 45 %
        ← ваш

Ф1 АБО Ф2 разом                                            7 з 11 = 64 %
```

**Мій фільтр закриває не половину, а трохи більше чверті.** Ваш —
ефективніший за мій майже вдвічі.

### Чому решта 4 фрази проходять обидва

```
SO8145  «класичний вібратор» на вібраторі з електростимуляцією
SO6986  «класичний вібратор» на кліторальному
        → «класичний» Є в характеристиці «Тип товару: класичний вібратор»
        → характеристика підтверджує САМА СЕБЕ

SO1825  «лубрикант на водній основі» на силіконовому
SX3922  «вібратор на водній основі»
        → помилка в прийменниковому хвості, а не в означенні
```

Перше — окрема пастка: **якщо приймати характеристику як джерело
підтвердження, хибний параметр підтверджує сам себе.** Той самий тип помилки,
що й у `head_noun`, тільки на рівень вище.

### Строгий варіант: 100 % влучення й повна непридатність

Перевірив найсуворіший фільтр — **кожне** змістовне слово фрази має бути в
**назві** цілим словом, характеристики як джерело не приймаються:

```
ловить хибних фраз типу Р          : 11 з 11 = 100 %
позначає на 300 випадкових картках : 1471 із 1836 фраз = 80 %
```

Ідеальна повнота й катастрофічна точність. Як **правило** непридатний: він
позначить чотири фрази з п'яти, зокрема цілком коректні категорійні
(«вібратори», «інтимні іграшки»), яких у назві немає й бути не має.

**Висновок, який мені не подобається, але він однозначний: вихідним фільтром
тип Р не лікується.** Або фільтр пропускає більшість помилок, або відкидає
більшість правильних фраз. Виправляти треба `head_noun()` на вході.

Фільтр лишається корисним в одній ролі — **як сигнал пріоритету** для черги
ручного перегляду: чим більше слів фрази відсутні в назві, тим підозріліша.
Але не як ворота.

## 2. RU генерується ОКРЕМИМ шляхом — фікси UA туди не перейдуть

Перевірив імпорти. `ru_keywords()` у `noire_prom_generator.py` бере з
`prom_keywords` **рівно одну функцію**:

```python
from prom_keywords import brand_cyr as _bcyr
```

`head_noun()`, `word_gender()`, `agree()` там **не використовуються взагалі**.
Рід береться зі свого джерела — `_load_ru_cat()`, який повертає
`(single, gender, purpose)` з російського довідника категорій.

**Отже:** RU-поле потребує **власного аудиту тим самим методом**, а не
успадкує виправлення UA. Це стосується й трьох щойно знайдених дефектів — у
RU вони можуть бути присутні в іншій формі або відсутні зовсім, і поки я
цього не знаю.

Плюс уже виміряні специфічно RU-проблеми: обрив на прийменнику 576 карток
(10.8 %), дублювання наборів 3637 карток (68 %), і випадок SO9465, де шкіряні
трусики описані як страпон.

## 3. Обсяг вибірки: ваша прикидка вдвічі оптимістична

Порахував інтервалом Вілсона для однієї частки, 95 %, за очікуваної частки
20.8 % (з першого прогону `head_noun`):

```
   n=40  → ±12.3 %
   n=60  → ±10.1 %
   n=80  → ± 8.8 %      ← ваша оцінка 60-80 дає сюди
   n=100 → ± 7.9 %
   n=150 → ± 6.5 %      ← ±7 % досягається тут
   n=300 → ± 5.0 %
```

**±7 % потребує 150 карток, не 60-80.** На 80 півширина ±8.8 %, тобто
істинна частка десь між 13 % і 31 % — для рішення про правку, що зачіпає
1870 карток, це завузько.

**Пропоную 150** як робоче число. Це приблизно три години ручного перегляду,
але вони дешевші за помилкову правку на 1870 картках.

## 5. Питання архітектури — зафіксовано, і воно сильніше, ніж здається

Ваша теза: частину фраз можна брати **прямим витягом з уже верифікованого
тексту**, де слово вже стоїть у правильній формі, замість генерації через
крихкий шар узгодження.

Записую як пункт для власника. Але додам виміряне, що робить її сильнішою:

Строгий фільтр показав, що **80 % наших фраз не мають дослівного підтвердження
в назві**. Тобто чотири фрази з п'яти проходять через шар генерації, де
можливі всі три щойно знайдені дефекти. Це і є та частка, про яку ви питаєте.

Застереження проти повного переходу на витяг у мене теж є, і воно виміряне:
саме витяг з опису (шар 3) дав «лубрикантом водній» і «означає насадка», бо
текст постачальника не складається з готових пошукових фраз. Тобто витяг
знімає проблему **форми**, але не проблему **вибору**.

Розумний варіант, схоже, посередині: витягати з **назви** (вона коротка,
структурована й перевірена людиною), а не з опису. Але це гіпотеза, і я її
не міряв.
