## 2. Знайдено дефект у коді, що обробляв тексти постачальника

Це найважливіше за сьогодні. Власник казав «проблема з кодом, що обробляв тексти
постачальника» — я знайшов конкретне місце.

Файл `tools/prom_kw_matrix.py`, блок «шар 3: предметні словосполучення з опису»
(рядки 452–472). Він бере **біграми сусідніх слів з опису** і кладе їх у слоти
`keywords_ua`. Мали спрацювати три запобіжники, і головний з них зламаний:

```python
def _is_adj(w):
    return w.endswith(('ий','ій','не','ні','ове','ова','а','я'))
...
a0 = _is_adj(words[i]); a1 = _is_adj(words[i+1])
if not (a0 ^ a1):        # має пропускати лише «означення + іменник»
    continue
```

Закінчення `а`, `я`, `ні` — це не лише прикметники, а **іменники в родовому й
місцевому відмінку**: «лубрикант**а**», «страпон**а**», «ван**ні**», «олі**я**».
Вони проходять як «означення», XOR виконується, і склейка з тексту потрапляє у фід.

### Що це дає на виході (виміряно на всьому фіді)

Решта — склейки з поламаним узгодженням: «силіконовий фалоімітат**ом**»,
«лубрикант**ом** водн**ій**», «означає насадка». **Оцінка моя і оспорювана** —
тому наводжу сирий список, щоб ви могли перерахувати самі.

### Другий, менший дефект — числові HTML-ентіті

```python
plain = re.sub(r'&\w+;', ' ', plain)
```

`\w+` не матчить `#39`, бо `#` не є символом слова. Тому `&mdash;` і `&rsquo;`
знімаються, а `&#39;` — ні. Словниковий регекс обривається на `&`, і
«підв**&#39;**язками» стає «підв».

```
описів із числовими ентіті              : 968 (18.0 %)
карток, де уламок ПОТРАПИВ у keywords_ua:  14
приклади: SO4509 SO4511 SO4512 SX2280 SX2282 «підв», HM-30-LI «пом»
```

14 карток — дрібниця проти 2574, але баг однорядковий і чиниться разом.

### Чого цей дефект НЕ пояснює

Сміттєвий ключ **не прибирає картку з видачі за її власною точною назвою**.
Тому це окремий дефект якості, а **не** причина «1 з 12». Не змішую.
