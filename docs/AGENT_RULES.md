# Правила розробки агентів — ОБОВ'ЯЗКОВО ЧИТАТИ ПЕРЕД БУДЬ-ЯКИМИ ЗМІНАМИ

## 1. ЗАБОРОНЕНО без явного дозволу користувача
- Змінювати будь-який існуючий агент (rozetka_order_agent.py, epicentr_order_agent.py, tg_dispatcher/main.py)
- Змінювати crontab на сервері
- Перезапускати systemd сервіси (rozetka-order-agent, epicentr-order-agent, tg-dispatcher, feed-server)
- Змінювати .env файл
- Видаляти або перезаписувати дані в БД
- Робити git push з незакоміченими змінами

## 2. ОБОВ'ЯЗКОВО перед будь-якою зміною в існуючому коді
- Прочитати файл повністю перед редагуванням
- Зробити резервну копію: cp file.py file.py.bak
- Перевірити синтаксис: python3 -c "import ast; ast.parse(open('file.py').read())"
- Описати ПОВНІСТЮ що змінюється і чому в commit message
- Після зміни перевірити що сервіс все ще працює: systemctl --user status {service}

## 3. ПРАВИЛА git
- Завжди git pull --rebase перед git push
- Якщо є незакомічені зміни — спочатку git stash або git add + git commit
- Ніколи не робити git push --force
- Commit message має містити: що змінено, чому, який файл

## 4. ПРАВИЛА для нових агентів
- Нові агенти створювати в agents/orders/ з назвою {supplier}_order_agent.py
- Нові інструменти створювати в tools/
- Новий сервіс systemd — тільки після тестування і явного дозволу користувача
- Новий cron — тільки після тестування і явного дозволу користувача

## 5. АКТИВНІ СЕРВІСИ — НЕ ЧІПАТИ БЕЗ ДОЗВОЛУ
- rozetka-order-agent — обробляє замовлення Розетки кожні 5 хв
- epicentr-order-agent — обробляє замовлення Єпіцентру кожні 5 хв
- tg-dispatcher — Telegram бот (PDF, команди, голос)
- feed-server — HTTP сервер фідів

## 6. АКТИВНІ CRON — НЕ ЧІПАТИ БЕЗ ДОЗВОЛУ
- 0 8 * * * price_updater.py — оновлення цін Prom
- 0 */4 * * * feed_sync.py — синхронізація Єпіцентр
- 0 * * * * rozetka_github_sync.py — Carvol XML push

## 7. ПОРЯДОК РОБОТИ З АГЕНТОМ
1. Прочитати поточний код повністю
2. Описати що треба змінити і отримати підтвердження
3. Зробити зміну мінімально — тільки те що потрібно
4. Перевірити синтаксис
5. Скопіювати на сервер через scp
6. Перевірити що сервіс запустився
7. Подивитись лог на помилки
8. git commit з детальним описом
9. git push

## 8. ПРАВИЛА ОПИСУ ЗМІН
Кожна зміна в існуючому файлі має містити:
- Що було до змін (старий код)
- Що стало після (новий код)
- Причина зміни
- Який ефект на систему
- Чи потрібен перезапуск сервісу

## 9. ЗАБОРОНЕНІ ПАТЕРНИ
- Ніколи не використовувати > для перезапису існуючих файлів агентів
- Ніколи не робити sed -i без попереднього резервного копіювання
- Ніколи не змінювати логіку обробки замовлень без тестування
- Ніколи не додавати нові залежності (pip install) без перевірки

## 10. ЯКЩО ЩОСЬ ЗЛАМАЛОСЬ
1. НЕ ПАНІКИ — не роби додаткових змін
2. Перевір git log --oneline -5 щоб знайти останній робочий коміт
3. git revert HEAD або git checkout {commit} -- file.py
4. Скопіювати виправлений файл на сервер
5. Перезапустити сервіс
6. Повідомити користувача
