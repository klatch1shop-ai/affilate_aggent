## Самостійні рішення

- Нові виконавці Rozetka додаються лише за наявності відповідних методів адаптера. Це зберігає сумісність зі старими адаптерами й тестом `test_fetchers_only_for_given_dependencies`, який передає адаптер лише з двома старими методами. Повний адаптер отримує всі передбачені завданням виконавці.
- Для `invoices` каталог містить намір, але завдання не визначає виконавця чи формат відповіді: запис є в `ALL_COMMANDS`, залежність не підключається.
- Невідомі значення полів відображаються як `—`, нулі зберігаються. Невідомий стан наявності також відображається як «невідомо»; текст звичайний, без Markdown-виділення.
- Артикул із `sku` використовується також за порожнього `article`; вхідний словник параметрів не змінюється.
- Мітки майданчиків у чатах взято з наявного `tg_dispatcher.inbox.render.LABELS`.
- Непідтримуваний статус пошуку спричиняє видиму помилку через наявний обробник `dispatch`, а не порожню успішну відповідь.
- Додано рядок «Непереглянутих» для переданого лічильника `unwatched`. Період передається виконавцю, але додаткова фільтрація за датами не реалізована: завдання визначає лише фільтр за групою статусу та ТТН.
