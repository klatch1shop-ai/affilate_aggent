- `tg_dispatcher/ai_brain/commands.py` — змінено лише гілку винятку `dispatch`: причина додається для `ApiError` і нащадків; за відсутності `integrations` або іншого винятку текст причини прихований.

## Перевірка

Щоб не створювати побічних файлів, перевірки виконано з вимкненими bytecode та кешем pytest.

Команда:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTEST_ADDOPTS='-p no:cacheprovider' venv/bin/python -m pytest tests/test_helper.py -q
```

Дослівний вивід, код завершення 0:

```text
................                                                         [100%]
16 passed in 0.02s
```

Команда:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTEST_ADDOPTS='-p no:cacheprovider' venv/bin/python -m pytest tests/ -q -k "not helper"
```

Дослівний вивід, код завершення 0:

```text
........................................................................ [ 31%]
........................................................................ [ 62%]
........................................................................ [ 94%]
.............                                                            [100%]
229 passed, 16 deselected in 0.20s
```

Додатковий одноразовий сценарій через `PYTHONDONTWRITEBYTECODE=1 venv/bin/python -` перевірив шість положень маркера біля межі 64 КіБ, обробку винятку за недоступного імпорту `integrations.errors` і відмову в доступі для bool, float, некоректних рядків та контейнерів. Тимчасові файли створювались лише в `/tmp` і видалені. Дослівний вивід, код завершення 0:

```text
Додаткові перевірки: межі блоків, відсутній integrations, некоректні ID — OK
```

`git diff --check` — без виводу, код завершення 0. Початковий робочий стан був чистий; зміни обмежені дозволеними файлами. Тести не змінено.

## Самостійні рішення

- Відповідно до §9 завдання, аварія процесу між `collect_rozetka()` і `queue.push()` може залишити повідомлення без картки в черзі. Воно зберігається у `store` як вхідне без відповіді, і нагадування покаже чат після встановленого інтервалу, якщо він досі очікує відповіді. Спільної транзакції між сховищем та чергою не додано.
- Успішне надсилання та локальні записи також не є спільною транзакцією: аварія після надсилання, але до видалення з черги може спричинити повторну картку. Це реалізація заданої послідовності, без гарантії одноразової доставки.
- Стан надісланих тривог і нагадувань зберігається в пам'яті екземпляра; персистентність за завданням забезпечена для черги. Після перезапуску можливе повторне сповіщення.
- Набори помилок порівнюються незалежно від порядку; однакові рядки в тривозі не дублюються. Стан оновлюється лише після успішного `send`, включно з повідомленням про відновлення.
- Помилка доставки має сталий безпечний текст без вмісту винятку. Помилки збору додатково маскуються, а в HTML-тексті тривоги екрануються.
- Чат у нагадуваннях визначається парою `(marketplace, chat_id)`; невдале надсилання не змінює час або набір останнього успішного нагадування.
- Фіди читаються двійковими блоками 64 КіБ зі збереженням останніх шести байтів. `OSError` під час читання, як і під час `stat`, означає недоступний фід.
- `is_allowed` не приймає bool або float як ID; рядковий ID має складатися з десяткових цифр.
