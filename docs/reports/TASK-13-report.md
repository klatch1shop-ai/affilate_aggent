```sh

```

```sh
PYTHONDONTWRITEBYTECODE=1 PYTEST_ADDOPTS='-p no:cacheprovider' venv/bin/python -m pytest tests/ -q -k "not confirm"
```
Дослівний вивід, код завершення 0:

Додатковий одноразовий Python-сценарій через stdin, без додавання файлів тестів, перевірив: порядок ключів при дедуплікації; підтвердження точно на межі TTL; повторний вкладений запуск через інше з'єднання; маскування успішного результату; незмінність завершеної дії при reject; прострочення TTL=0; межу строку ack; відхилення часу без зони.

`git diff --check` — код завершення 0, вивід порожній. Початковий `git status --short` був порожнім; після реалізації були лише два нові дозволені модулі, після оформлення додано цей звіт.

## Самостійні рішення

- Завершені рішення не змінюються через approve/reject; прострочення стосується лише pending. Це узгоджено з приймальним тестом відхиленої дії.
- Перед create прострочені pending позначаються expired, щоб можна було запропонувати дію знову. Канонічний JSON використовується лише для дедуплікації; первинний порядок параметрів збережено для показу. Транзакція й частковий унікальний індекс захищають від дублювання між з'єднаннями.
- TTL=0 означає нульовий строк; типовий TTL застосовується лише за ttl_min=None. Підтвердження дозволене точно на expires_at, позначка ack на until уже не чинна.
- Невідомий id у методах прийняття рішення спричиняє ValueError; get повертає None, run_action повертає ok=False/status=missing. Від'ємний ліміт журналу та невідомий ризик у gate відхиляються.
- Залишок хвилин у confirm_text обчислюється від поточного UTC, округлюється вгору, мінімум 0.
- Внутрішня ознака claimed атомарно резервує виконання до виклику executor. Повторне виконання через інше з'єднання блокується, без утримання транзакції під час executor.
- user_id у run_action залишено в заданому інтерфейсі; правила доступу перевіряє оболонка, оскільки завдання не задає списку авторизованих користувачів. dry_result також збережено в інтерфейсі без спеціальної поведінки: за алгоритмом завдання записується фактичний результат executor.
- chat_id нормалізується до рядка; last_msg_id зберігається як JSON. acked повертає лише чотири задані поля; ack додатково повертає last_msg_id.
