# Звіт TASK-05: адаптери API лише для читання

## Що зроблено

- `integrations/__init__.py` — порожній файл пакета.
- `integrations/errors.py` — `ApiError`, `AuthError`, `NotFound`; форматування коду й маскування всього тексту через `mask_private`.
- `integrations/retry.py` — обмежені повтори з переданою функцією очікування, пробрасування останнього винятку.
- `integrations/rozetka.py` — спільний розбір конверта, класифікація помилок, пагінація з відмовою від неповного списку, об'єднання активних замовлень, читання одного замовлення й чатів. Замовлення очищуються за білими списками.
- `integrations/novaposhta.py` — перевірка ТТН, формування запиту статусу, повтори при ліміті та порожньому списку даних, повернення лише дозволених полів.
- `integrations/prom.py` — читання повідомлень і замовлень, перевірка ліміту перед запитом, явні помилки авторизації та некоректної відповіді.

Усі клієнти використовують лише переданий транспорт. Мережевих викликів, читання секретів, встановлення пакетів і комітів не виконувалося. Тести й інші файли репозиторію не змінювалися.

## Перевірка

Для запусків вимкнено запис байткоду й кешу pytest, щоб не створювати побічних файлів.

```sh
PYTHONDONTWRITEBYTECODE=1 PYTEST_ADDOPTS='-p no:cacheprovider' venv/bin/python -m pytest tests/test_integrations.py -q
```

Дослівний вивід, код завершення 0:

```text
..................................                                       [100%]
34 passed in 0.02s
```

```sh
PYTHONDONTWRITEBYTECODE=1 PYTEST_ADDOPTS="-p no:cacheprovider" venv/bin/python -m pytest tests/ -q -k "not integrations"
```

Дослівний вивід, код завершення 0:

```text
........................................................................ [ 36%]
........................................................................ [ 73%]
...................................................                      [100%]
195 passed, 34 deselected in 0.19s
```

Додаткова перевірка через `PYTHONDONTWRITEBYTECODE=1 venv/bin/python -` на підставлених функціях транспорту: вичерпання чотирьох спроб після `TimeoutError` у Prom і НП із затримками `[1, 2, 4]`; приховування тестового ключа й телефону в помилках Rozetka і НП. Також перевірено приховування контексту транспортного винятку. Код завершення 0, дослівний вивід:

```text
Додаткові перевірки: 4 сценарії пройдено.
```

`git diff --check` — код завершення 0, вивід порожній. До початку роботи `git status --short` був порожнім; після реалізації з'явилися лише шість дозволених файлів `integrations/`, до яких додано цей звіт.

## Самостійні рішення

- Порожні після видалення крайових пробілів ключі також відхиляються в конструкторах.
- `max_pages` має бути додатним цілим числом; ліміт Prom — цілим числом 1–100, без приймання булевих значень.
- Некоректна структура відповіді, зокрема відсутня метаінформація пагінації Rozetka або неправильний тип даних НП, спричиняє `ApiError`. Відсутні дані НП не прирівнюються до коректного порожнього списку `data=[]`.
- При дублюванні замовлення перемагає запис із `orders(2)`, прочитаний після `orders(4)`.
- У ТТН видаляються всі пробільні символи; номери замовлень і ТТН перевіряються на ASCII-цифри.
- Транспортні повтори НП із затримками `(1, 2, 4)` відокремлено від повторів відповідей про ліміт або порожні дані із затримками `(5, 15, 30)`.
- У текстах помилок API додатково приховується точний збіг переданого ключа, якщо сервер відобразить його у відповіді. Текст транспортного винятку не додається до `ApiError`, його контекст приховується через `from None`.

## Що не вдалося, питання

Невдалих перевірок і відкритих питань немає. Живі API не перевірялися згідно із забороною зовнішніх дій; перевірка виконана на підроблених даних.
