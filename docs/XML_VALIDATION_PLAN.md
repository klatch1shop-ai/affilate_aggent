## 2. Формат categoryId — rz_id чи внутрішній?

**Відповідь: rz_id — обов'язково.**

З `api_full.txt`:
> `rz_id в XML має вищий пріоритет над текстовою назвою`

З `xml_requirements.txt` (офіційна документація Розетки):
```xml
<categories>
  <category id="391">Куртки для хлопчиків</category>
</categories>
<offers>
  <offer id="19305">
    <categoryId>391</categoryId>  ← внутрішній id магазину
```

**Критичне уточнення:** `<categoryId>` в офері посилається на `id` з секції `<categories>`, а не напряму на Розеткин rz_id. Розетка сама матчить через поле `rz_id` або через назву категорії.

**Поточний стан нашого XML:**
```xml
<categories>
  <category id="80140">Кухонні витяжки</category>  ← id = rz_id безпосередньо
</categories>
<offers>
  <categoryId>80140</categoryId>  ← відповідає id з categories
```

Це **правильний підхід** — ми використовуємо rz_id як id категорії в XML. Розетка прийматиме ці ID як посилання на свої категорії напряму. Підтверджено: [xml_requirements, приклад YML].

## 5. Поле vendor — обов'язкове чи ні?

**Відповідь: ОБОВ'ЯЗКОВЕ.**

З `brand.txt`:
> `Бренд (торгова марка / виробник) — це обов'язкова інформація, яка має бути вказана в назві товару та в тегу <vendor> в xml прайс-листі`

**Поточний стан:**
- Всі 7417 офферів мають `<vendor>` — ✅
- **191 оффер мають `<vendor>no name</vendor>`** — ⚠️ ПРОБЛЕМА

З `brand.txt`:
> `Якщо бренд невідомий чи вигаданий — заповнюйте інформацію, як для товару «без бренду»`
> Без бренду можна: банкноти, хенд-мейд, продукти харчування, комплекти

191 товарів з "no name" = ноутбуки/техніка без вказаного бренду в Katran. Це НЕ входить у виключення. Такі товари Розетка відхилить при модерації.

## 6. Конкретні виправлення для проходження валідатора

### КРИТИЧНІ (XML не пройде валідацію)

#### 6.1 — 4 дублікати offer id
**Знайдено:** 4 артикули зустрічаються двічі: `506634`, `CW-1031`, `P5148`, `R-AG300-BKLNMN-G`

Розетка **забороняє** дублікати ID у XML (ID товару — унікальний ідентифікатор).

**Виправлення в `katran_xml_generator.py`:**
```python
seen_ids = set()
for o in offers_data:
    if o["artikul"] in seen_ids:
        continue  # пропустити дублікат
    seen_ids.add(o["artikul"])
    # ... генерація XML
```

#### 6.2 — Назва починається з `!`
**Знайдено:** 1 оффер: `!Папір А3 R-COPY STANDART 80 г/м2...`

Заборонено: `Назва має починатись з великої (заголовної) літери` — цифри і символи недозволені як перший символ.

**Виправлення в `fix_name()` в `katran_xml_generator.py`:**
```python
def fix_name(name: str, artikul: str) -> str:
    name = re.sub(r'^[!@#$%^&*\-_ ]+', '', name).strip()  # прибрати ведучі символи
    if not name:
        return artikul
    name = re.sub(r"\s+", " ", name).strip()
    return name[:255]
```

### ВИСОКИЙ ПРІОРИТЕТ (товари не публікуватимуться)

#### 6.3 — 55.3% товарів у DEFAULT категорії 25636737
**Знайдено:** 4101 оффер → "Ручний інструмент"

Більшість цих товарів (смартфони, планшети, кабелі, канцтовари) не мають відношення до "Ручний інструмент". Розетка їх відхилить або не покаже.

**Варіанти вирішення (на вибір):**

A) **Виключити незмапповані з XML** (найбезпечніше):
```python
# У generate_xml() замінити:
rz_id = cat_info.get("rz_id", DEFAULT_RZ_ID)
# На:
rz_id = cat_info.get("rz_id")
if not rz_id:
    skipped_unmapped += 1
    continue  # пропустити якщо не змаппована
```
Результат: XML матиме ~3316 правильних офферів замість 7417 з помилками.

B) **Домапити залишок** (більше товарів, але треба час):
Додати rz_ids для IT-категорій (смартфони, планшети, мікрофони, кабелі, картриджі). ~350 категорій, потребує перевірки через PriceCreator.

#### 6.4 — vendor="no name" у 191 офферів
Бренд обов'язковий. Товари з "no name" не пройдуть модерацію.

**Виправлення:** В `katran_xml_generator.py` пропускати товари без реального бренду або замінити "no name" на "No brand":
```python
vendor = clean_text(p.findtext("vendor") or "")
if not vendor or vendor.lower() in ("no name", "noname", ""):
    vendor = "No brand"
    # Або: continue  # пропустити без бренду
```

#### 6.5 — "Гарантія: 0 міс" у 2558 офферів
Для побутової техніки документація вимагає вказати гарантію. Відправляти "0 міс" — це не "гарантія відсутня", а явна відмова від гарантії, що є маркетинговою проблемою.

**Виправлення:** не додавати param Гарантія якщо warranty=0:
```python
# У generate_xml() при формуванні offer:
if o["warranty"] and o["warranty"] != "0":
    offer.append(f'<param name="Гарантія">{xml_escape(o["warranty"])} міс</param>')
```

### СЕРЕДНІЙ ПРІОРИТЕТ (знизить якість, але не заблокує)

#### 6.6 — 98 назв починаються з цифри
Документація: `Назва має починатись з великої (заголовної) літери`.

Приклади: `16GB DDR4 Crucial...`, `10 mm*1.8 m Refill...`

**Виправлення:** В `fix_name()` додати трансформацію:
```python
# Якщо перший символ — цифра або мала, спробувати знайти тип товару з назви
# Або просто залишити — Розетка при модерації попросить виправити конкретні
```
Це складно автоматизувати. Краще фіксити вручну при модерації.

#### 6.7 — Тільки 3 `<param>` на кожен оффер (Бренд, Гарантія, Артикул)
Документація: `Мінімальна кількість характеристик — 3` — ми виконуємо мінімум.
Але для побутової техніки: `Обов'язково: гарантія, штрихкод виробника, мін 3 характеристики`.

Рекомендація: додати більше param з даних фіду якщо є:
- `<param name="Тип товару">...</param>`
- `<param name="Колір">...</param>`
- `<param name="Потужність">...</param>` (для техніки)

Катран у фіді не надає такі дані, тому поки неможливо без ручного збагачення.

#### 6.8 — `<shop><url>` вказує на prom.ua
Поточне: `<url>https://prom.ua/ua/c3882792-hyper-store.html</url>`

Має бути URL Розетка-магазину або залишити будь-який статичний URL. Не критично для валідації, але некоректно.

**Виправлення в `katran_xml_generator.py`:**
```python
SHOP_URL = "https://seller.rozetka.com.ua/"  # або будь-який статичний URL
```

#### 6.9 — Деякі артикули містять пробіли і спецсимволи
Артикул = ID offer в XML. Спецсимволи в ID потенційно проблемні, але XML escape вже застосовується.
