## 1. Навіщо

Бот розуміє 9 команд. Матриця (§3 плану) додає ≈16 команд читання (R0). Нинішній розбір —
ключові слова, і нові команди з ними конфліктують: «скільки замовлень» зараз іде в `stock`
(слово «скільки»), «замовлення без ттн» — у `ttn_status`, «повернення по 906…» — у

слова**, і **каталог команд** — єдине джерело назв, прикладів і рівнів ризику (з нього
будуть довідка, меню, а у фазі B — підтвердження записів).

## 4. Нові параметри (`params`)

| ключ | коли | значення |
|---|---|---|
| `status` | слова про стан замовлень | `cancelled` (скасован*, отмен*), `completed` (виконан*, доставлен*, отриман*), `delivering` (в дорозі, доставляються, отправлен*) |
| `source` | назва постачальника/джерела | `toptul`, `noire`, `dropoffice`, `carvol` (регістр і відмінки: «топтул», «toptul», «нуар», «noire», «дропофіс», «карвол», «carvol») |
| `goods_tab` | про товари на майданчику | `moderation` (модерац*), `errors` (помилк*), `hidden` (прихован*) |
| `article` | артикул постачальника: 2–6 латинських літер + 3–8 цифр, можливо з літерами/дефісом у кінці (напр. `KAAA1404`, `GAAI4601-B`) | верхнім регістром; **лише** якщо нема `sku` NOIRE (старий `_SKU_RE`). **Шукати в сирому тексті**: нормалізація прибирає дефіс |

Старі параметри (`ttn`, `order_id`, `sku`, `marketplace`, `period`) — без змін.

### 5.1. Порядок розбору (обов'язково — інакше конфлікти з §1)
1. **Комбінації номера з уточненням** (раніше за «номер ⇒ старий намір»):
   14 цифр + (етикетк*/надрукуй/друк*) → `label`; 9 цифр + повернен* → `refund_detail`;
   9 цифр + (викуп/рейтинг покупця) → `buyer_rating`.
2. Далі старі правила номерів: 14 цифр → `ttn_status`; 9 цифр → `order_status`.
3. `supplier_stock` — якщо є «у постачальника»/«у постачальників» і (`article` або `sku`) —
   **раніше** за старе правило «`sku` ⇒ `stock`».
4. Старе правило `sku` ⇒ `stock` / `price_alerts`.
5. **Фрази-комбінації без номерів** (раніше за окремі ключові слова): «без ттн» →
   `orders_without_ttn`; «ттн від постачальник*»/«прийшли ттн» → `supplier_ttn`;
   «скільки/кількість замовлень|заказов» → `orders_counts`; `status` + замовлен*/заказ* →
   `orders_search`; «відгуки про магазин»/«оцінки магазину» → `shop_reviews` (раніше за
   `item_comments`).
6. Решта — ключові слова, як зараз.

Впевненість: правила 1–5 → `1.0`, якщо спрацювали на однозначній комбінації; ключові слова —
як зараз (`0.8`; загальне слово про ціну — `0.5`).

## 6. `tg_dispatcher/ai_brain/catalog.py`

```python
RISK_LEVELS = ('R0', 'R1', 'R2', 'R3')
CATALOG: dict[str, dict]     # намір → {'title': str, 'risk': str, 'needs': list[str], 'example': str, 'group': str}
GROUPS: tuple[str, ...]      # порядок груп для довідки
def by_group() -> dict[str, list[str]]
def help_text(available: set[str] | None = None) -> str
```
- `CATALOG` містить **усі** наміри з `intents.py`, крім `unknown` (8 старих + 17 нових).
- `risk`: усі поточні — `'R0'`. `needs` — як у таблиці §5 (для старих — як у `commands.COMMANDS`;
  для `supplier_stock` — `['article']`, бо `sku` приймається як артикул).
- `example`: фраза, яку `intents.parse` розпізнає **саме як цей намір** з `confidence >= 0.5`
  (перевіряється тестом для кожного запису).
- `group` — одна з `GROUPS = ('Замовлення', 'Посилки', 'Покупці', 'Повернення', 'Товари',
  'Постачальники', 'Гроші', 'Система')`.
- `by_group()` → `{група: [наміри в порядку CATALOG]}`, лише непорожні групи, у порядку `GROUPS`.
- `help_text(available)` — текст довідки: для кожної групи рядок `<група>:`, далі рядки
  `• <title>: «<example>»`. Якщо передано `available` — лише наміри з цієї множини (і групи без
  жодного — не показувати). `help` у довідці не показується.
