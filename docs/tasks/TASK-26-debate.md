## Інтерфейс
```python
SIDES = ('за', 'проти')
def build_prompts(claim: str, evidence: list[dict]) -> dict
def parse_side(text: str) -> list[dict]
def merge(pro: list[dict], con: list[dict], evidence: list[dict]) -> dict
def report(claim: str, merged: dict) -> str
```
Доказ — `{'id': 'e1', 'text': '5 питань про сумісність за тиждень'}`.

### `build_prompts(claim, evidence)`
Повертає `{'за': <текст>, 'проти': <текст>}`. Кожен текст містить: тезу, **усі** докази
рядками `'[e1] текст'`, вимогу відповісти **JSON**-списком `{'point', 'refs'}`, вимогу
**посилатися лише на наведені `id`** і пряму заборону вигадувати нові факти.
Порожній `claim` або порожній `evidence` → `ValueError`.

### `parse_side(text)`
Розбирає відповідь (можлива огортка ```` ```json ````). Не JSON або не список → `ValueError`.
Кожен елемент → `{'point': str, 'refs': list[str]}`:
- `point` обрізається; елемент без `point` (або порожній) — **пропускається**;
- `refs` — рядок зводиться до списку з одного елемента; відсутні → `[]`; кожен `id` обрізається;
- інші ключі відкидаються.

### `merge(pro, con, evidence)`
Повертає `{'for', 'against', 'dropped', 'unused', 'balance'}`:
- теза лишається, якщо `refs` **непорожні** і **всі** `id` є серед доказів;
- інакше — у `dropped`: `{'side', 'point', 'reason'}`, де `reason` — `'без доказу'`
  (порожні `refs`) або `'невідомий доказ: e9'` (перший невідомий `id`);
- `for` і `against` — `[{'point', 'refs'}]` у вхідному порядку;
- `unused` — `id` доказів, на які не послалася **жодна** сторона, у порядку `evidence`;
- `balance` — `'за'`, якщо зарахованих «за» більше; `'проти'`, якщо більше «проти»;
  рівно — `'рівно'`; **якщо в однієї зі сторін нема жодної зарахованої тези — `'однобоко'`**
  (це сигнал, що спору не вийшло).

### `report(claim, merged)`
```
⚖️ <claim>
За (2):
• <теза> [e1]
• <теза> [e2, e3]
Проти (1):
• <теза> [e2]
Відкинуто без доказу: 1
Не використані докази: e4
Підсумок: рівно
```
- розділ `Проти` з `(0)` і рядком `• —`, якщо порожній (те саме для `За`);
- рядки `Відкинуто…` і `Не використані…` виводяться **лише** якщо непорожні;
- останній рядок завжди `'Підсумок: <balance>'`.

## Відповіді на можливі питання
1. **Дублі `id` у `refs`** — лишаються як є; на «використаність» доказу впливає сам факт посилання.
2. **Однакова теза з обох боків** — обидві лишаються, це нормально для спору.
3. **`evidence` з дублями `id`** — `ValueError` у `build_prompts`; у `merge` такого не перевіряти.
4. **Порядок `dropped`** — спершу всі відкинуті «за», потім «проти», у вхідному порядку.
