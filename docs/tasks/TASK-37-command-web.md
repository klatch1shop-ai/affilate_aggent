# ЗАВДАННЯ 37: павутина команд — логічна матриця дій для 3 маркетплейсів, Нової Пошти і бекенду

**Запит власника (03.10.2026):** «павутина команд, логічна матриця дій та різних
можливих поєднань для 3 маркетплейсів і усіх їх доступних api методів, і додати
роботу з api Нової Пошти, розробки повного стеку бекенду для цього функціоналу».
**Термін:** доба, тобто до 04.10.2026.
**Окремо:** робота по Prom не зупиняється.

## Що це означає

Зараз кожна дія з маркетплейсом — окремий скрипт: 60+ файлів `tools/prom_*`,
`tools/toptul_*`, `tools/noire_*`. Вони не знають один про одного, і одна й та
сама операція (оновити наявність) реалізована окремо для кожного каналу — саме
через це 02.10 TOPTUL і dropoffice місяць стояли без синхронізації, бо для
NOIRE її писали окремо.

Павутина команд — це опис **дій**, а не скриптів: що взагалі можна зробити з
товаром, замовленням і доставкою, якими методами API це доступно на кожному
майданчику, і які поєднання дій мають сенс.

## Крок 0 (обов'язковий, за методом): інвентаризація РЕАЛЬНИХ методів

Не з документації й не з памʼяті — **викликом**. Записувати лише те, що
відповіло. Підстава: з 82 моделей NVIDIA NIM працювала одна; у Prom «21 метод»
виявились без аналітики; у Єпіцентрі `page` ігнорується, працює лише `cursor`.

| канал | що перевірити |
|---|---|
| Prom | `/products/*`, `/groups/*`, `/orders/*`, `/messages/*`, `/clients/*`, доставка, оплата |
| Rozetka | методи кабінету продавця, чати, замовлення, ТТН |
| Єпіцентр | PIM `core-api.epicentrm.com.ua`, OMS, коментарі модерації |
| Нова Пошта | створення ТТН, статуси, довідники, післяплата |

Для кожного методу: HTTP-код, які поля повертає, які приймає, обмеження
(пагінація, квоти, що мовчки ігнорується).

## Що має вийти

1. `docs/research/COMMAND_WEB.md` — матриця «дія × канал × метод API × обмеження».
2. Перелік дій, доступних на одному каналі й недоступних на іншому — саме там
   виникають дірки на кшталт тієї, що дала замовлення на відсутній товар.
3. Схема бекенду: один шар дій над каналами, щоб нова дія писалась один раз.
4. Нова Пошта як окремий канал: що ми вже вміємо (`toptul_ttn_reconcile.py`,
   блок післяплати на карту — API 20000201794) і чого бракує.

## Перевірка (щоб не повторити помилок 02–03.10)

- кожне число в матриці — з реального виклику, не з довідки (скіл
  `measuring-before-reporting`);
- твердження «метод є» підтверджується кодом відповіді, «метод робить X» —
  полями у відповіді;
- гіпотези про архітектуру — через `tools/hypotheses.py --discuss` ДО коду.
