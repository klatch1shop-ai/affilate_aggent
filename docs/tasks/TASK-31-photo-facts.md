# ЗАВДАННЯ 31: перевірка фактів за фото упаковки

**Виконавець:** Codex. **Приймає:** рецензент за `tests/test_photo_facts.py`. **Дата:** 20.09.2026.
**Привід (реальний випадок 20.09):** у даних постачальника «190 г», на фото упаковки «180 g».
Помилка пішла б у картку маркетплейсу і в текст ролика. Треба модуль, який зводить
прочитане з фото з даними постачальника і показує розбіжності.

## Файли
Створити `content/photo_facts.py`. Лише стандартна бібліотека. **Без мережі**: читання фото
(Gemini) передається ззовні функцією, як `fetchers` у TASK-02 і `synth` у TASK-29.

## Інтерфейс
```python
UNITS: dict          # нормалізація одиниць
QUESTION: str        # запит до моделі, що читає фото
def parse_reading(text: str) -> dict
def numbers(text: str) -> list[tuple[float, str]]
def read_photos(paths, reader, *, limit=4) -> dict
def compare(supplier: dict, photo: dict) -> dict
def report(result: dict) -> str
```

### `QUESTION`
Текст запиту до моделі: вимагає **JSON**, перелічує поля `FIELDS`, і прямо забороняє вигадувати —
чого не видно на упаковці, те має бути `null`. Перевіряється тестом за наявністю слів.

### `FIELDS`
`('brand', 'name', 'volume', 'weight', 'country', 'ingredients', 'warnings')` — саме в цьому порядку.

### `parse_reading(text)`
Розбирає відповідь моделі. Приймає текст із огорткою ```` ```json … ``` ````. Не JSON → `ValueError`.
- Повертає словник **рівно з ключами `FIELDS`**; відсутнє поле → `None`.
- Порожній рядок, рядок із самих пробілів, `'null'`, `'-'`, `'n/a'`, `'невідомо'` → `None`.
- Значення-список (напр. `ingredients`) зводиться в рядок через `', '`.
- Значення-число зводиться в рядок.
- Усі рядки обрізаються пробілами.

### `numbers(text)`
Витягує з тексту числа з одиницями й нормалізує:
- десяткова кома = крапка: `'1,5 кг'` → `(1500.0, 'g')`;
- `UNITS`: `г|гр|g|grams` → `g`; `кг|kg` → `g` ×1000; `мл|ml` → `ml`; `л|l` → `ml` ×1000;
  `шт|pcs` → `pcs`; `%` → `%`. Регістр не має значення.
- одиниця може бути злитою з числом: `'57мл'` → `(57.0, 'ml')`;
- число без відомої одиниці **пропускається** (`'артикул 3142'` → `[]`);
- результат — у порядку появи, **без дублів** (те саме число+одиниця двічі → один раз).

### `read_photos(paths, reader, *, limit=4)`
`reader(path, question) -> str`. Питає **перші `limit`** шляхів, дублі шляхів пропускає.
Повертає `{'items': [...], 'merged': {...}, 'errors': [...]}`:
- `items` — `[{'path': ..., **розбір}]` лише для вдалих;
- виняток `reader` або `ValueError` розбору → рядок у `errors` виду `'<path>: <тип або причина>'`,
  обхід не зупиняється;
- `merged` — по кожному полю **перше непорожнє** значення в порядку фото.

### `compare(supplier, photo)`
Обидва — `поле -> рядок` (значення `photo` можуть бути `None`). Повертає
`{'match': [...], 'mismatch': [...], 'unreadable': [...], 'only_supplier': [...], 'only_photo': [...]}`.
Для кожного поля, що є в обох:
- `photo[поле] is None` → у `unreadable` (лише назва поля);
- якщо **в обох** сторонах є числа (`numbers`) → порівнюються **списки чисел**; рівні → `match`,
  інакше → `mismatch`;
- якщо чисел нема з жодного боку → порівнюється текст: нижній регістр, апостроф `’` = `'`,
  кілька пробілів = один, обрізані пробіли; рівні → `match`, інакше → `mismatch`;
- числа є лише з одного боку → `mismatch`.
- `match` — список назв полів. `mismatch` — `[{'field', 'supplier', 'photo'}]`.
- Поле лише в `supplier` → `only_supplier`; лише в `photo` (і не `None`) → `only_photo`.
Порядок усередині списків — порядок ключів `supplier`, потім `photo`.

### `report(result)`
Текст для власника:
- перший рядок: `'❗ Розбіжності: N'`, якщо `mismatch` не порожній, інакше `'✅ Розбіжностей немає'`;
- по рядку на розбіжність: `'• <поле>: постачальник «<X>» / упаковка «<Y>»'`;
- далі, у цьому порядку й лише якщо відповідний список не порожній:
  `'Збіглося: N'` (кількість `match`), `'Не прочитано на фото: a, b'` (`unreadable`),
  `'Немає на фото: a, b'` (`only_supplier`), `'Немає у постачальника: a, b'` (`only_photo`);
  назви полів через `', '` у порядку списку;
- усе порожнє → `'Нема даних'`.

## Відповіді на можливі питання
1. **Число + одиниця в одному полі кілька разів** (`'57 мл / 2 шт'`) — обидва потрапляють у список,
   порядок появи; порівняння списків чутливе до порядку.
2. **`supplier` містить `None`** — таке поле вважається відсутнім у постачальника: якщо у `photo`
   є значення, поле йде в `only_photo`.
3. **Регістр назв полів** не нормалізується: ключі беруться як є.
4. **`limit=0`** → жодного виклику `reader`, `items` і `errors` порожні, `merged` — усі `FIELDS`
   зі значенням `None`.
