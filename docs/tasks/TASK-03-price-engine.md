# ЗАВДАННЯ 03: калькулятор ціни для Rozetka (на прикладі TOPTUL)

**Виконавець:** безкоштовна модель (`tools/llm_delegate.py`).
**Приймає:** основна модель за тестами `tests/test_price_engine.py`.
**Дата:** 18.09.2026.

## 1. Навіщо

Ціна на Rozetka має рахуватися сама, з мінімальним втручанням людини, і
**ніколи не бути збитковою**. Зараз ціни TOPTUL рахуються вручну.

Цей файл — **лише математика**: без мережі, бази, файлів. Читання прайсу,
пошук конкурентів і звіти робить інший код, який викликає ці функції.

## 2. Терміни

| термін | зміст |
|---|---|
| `wholesale` | оптова (закупівельна) ціна, грн — наші витрати на товар |
| `rrp` | РРЦ постачальника, грн — **мінімальна ціна продажу**; продавати дешевше не можна за умовами постачальника |
| `ranges` | ступінчаста комісія Rozetka для категорії: список `[від, до, відсоток]`, межі включно, напр. `[[0, 4999, 18], [5000, 9999, 10], [10000, 999999999, 7]]` |
| `fixed_costs` | інші витрати на одиницю, грн (упаковка тощо), за замовчуванням 0 |
| `min_profit` | мінімальний допустимий прибуток з одиниці, грн, за замовчуванням 0 |
| `competitors` | ціни конкурентів **на той самий товар**, грн (точний збіг артикула — забезпечує викликач) |

**Прибуток** = `ціна − комісія(ціна) − wholesale − fixed_costs`.
**Комісія(ціна)** = `ціна × відсоток / 100`, де відсоток береться зі смуги, в яку потрапляє **сама ціна**.

## 3. Головна складність: комісія залежить від ціни

Ставка падає зі зростанням ціни (18 % → 10 % → 7 %). Тому «підняти ціну
на суму комісії» — циклічна задача: нова ціна може потрапити в іншу смугу.

**Правило пошуку ціни, яка покриває потрібну суму `need` після комісії:**
для кожної смуги `[lo, hi, pct]` рахується `p = need / (1 − pct/100)`.
Кандидат дійсний, якщо `lo ≤ p ≤ hi`. Якщо в смузі кандидат менший за `lo`,
але `lo − комісія(lo) ≥ need`, дійсним кандидатом є сам `lo`.
Береться **найменший** дійсний кандидат. Округлення — **вгору** до цілої гривні.

Приклад, який мусить працювати: `need = 4500`, смуги 18 % до 4999 і 10 %
від 5000. У смузі 18 %: 4500/0,82 = 5488 — поза смугою, недійсний. У смузі
10 %: 4500/0,9 = 5000 — у смузі. Ціна **5000**, а не 5488.

## 4. Що зробити

Один файл `tools/price_engine_toptul.py` з функціями:

```python
def commission_pct(price: float, ranges: list) -> float
def gross_up(need: float, ranges: list) -> int
def price_item(wholesale, rrp, ranges, competitors=(), min_profit=0.0,
               fixed_costs=0.0, undercut=0) -> dict
def summarize(results: list) -> dict
```

### 4.1. `price_item` — порядок розрахунку

1. Якщо `wholesale` або `rrp` відсутні (None) чи ≤ 0 → `status='no_data'`, `price=None`.
2. **Цільова ціна** (правило власника «спершу РРЦ + комісія»): `target = gross_up(rrp)`.
3. **Нижня межа** `floor = max(rrp, gross_up(wholesale + fixed_costs + min_profit))`,
   округлена вгору. Нижче неї ціна не буває **ніколи**: нижче РРЦ заборонено
   постачальником, нижче другого — збиток.
4. Ціна за замовчуванням `price = max(target, floor)`.
5. Конкуренти: `cmin = min(competitors)`, якщо список не порожній.
   - якщо `cmin − undercut < price` і `cmin − undercut ≥ floor` → `price = cmin − undercut`, статус `competitive`;
   - якщо `cmin − undercut < floor` → ціна лишається `max(target, floor)`, статус `uncompetitive`
     (нас дешевше продають, але в мінус не йдемо);
6. Якщо конкурентів немає: статус `raised_for_margin`, коли `floor > target`
   (РРЦ + комісія не покривали мінімальний прибуток), інакше `ok`.

### 4.2. Повертає словник рівно з ключами

`price` (int або None), `status`, `commission_pct`, `commission` (грн, 2 знаки),
`profit` (грн, 2 знаки), `margin_pct` (прибуток / ціна × 100, 1 знак),
`target`, `floor`, `competitor_min` (або None), `reason` (рядок українською:
чому саме така ціна).

`status` — один із: `ok`, `raised_for_margin`, `competitive`, `uncompetitive`, `no_data`.

### 4.3. `summarize(results)`

Словник: `total`, `by_status` (кількість за статусами), `priced` (скільки з
ціною), `avg_margin_pct` (середня по тих, що мають ціну, 1 знак, або None),
`min_profit` (найменший прибуток серед оцінених або None),
`losses` (скільки з `profit < 0` — **має бути 0 завжди**).

## 5. Незмінні правила (інваріанти)

- для будь-якого результату з ціною: `price ≥ rrp` і `profit ≥ min_profit`;
- `price` — ціле число;
- `commission_pct` відповідає смузі, в яку потрапила **остаточна** ціна;
- функції не звертаються до мережі, файлів, бази; лише стандартна бібліотека.
