# SKILL-34: Безкоштовні канали LLM і перемикання між ними

## 0. ГОЛОВНЕ З 19.09.2026 — канал Gemini (читати першим)

**Ключ:** `GEMINI_API_KEY` у `.env` сервера й ноутбука (від власника, AI Studio, **безкоштовний
тариф**). Формат ключа `AQ.…` — нового зразка, працює заголовком `x-goog-api-key`.
**Не** Google Cloud / Agent Platform: там ключ вимагає увімкнути оплату — власнику сказано не вмикати.

**Код:** `shared/utils/llm_router.py`, ланцюжок за замовчуванням `gemini,ollama`.
```python
from shared.utils.llm_router import ask
r = ask('…', task='text')                  # r['channel'], r['model'], r['ms']
```
```bash
venv/bin/python shared/utils/llm_router.py --selftest
LLM_COOLDOWN=0 venv/bin/python tools/llm_channel_bench.py --n 30 --channels gemini
```

### Замір 19.09 (30 справжніх товарів NOIRE, завдання «2 речення строго за даними»)

| | gemini-flash-lite-latest | ollama llama3.2:3b |
|---|---|---|
| відповіли | 30/30 | 30/30 |
| вигадані числа | 0 | 0 |
| мішанина мов | **0** | **11** («Гель-lubريكант») |
| медіана | **0,9 с** | 1,0 с (ноутбук), 2,3 с (сервер) |
| selftest-речення | точне визначення | «рідка мабула, що виростає на коралових рифах» (сервер) |

### Ліміти й моделі — перевірено запитами, каталогу НЕ вірити
| модель | стан 19.09 |
|---|---|
| `gemini-2.5-flash`, `gemini-2.5-flash-lite` | є в `/models`, але 404 «no longer available to new users» |
| `gemini-flash-latest` | працює, але **20 запитів/добу** (вичерпано першим же заміром) |
| `gemini-pro-latest` | 429 одразу (вхідні токени/добу на безкоштовному = 0) |
| `gemini-flash-lite-latest` | ✅ основна: 30 поспіль без відмов |
| `gemini-3.1-flash-lite`, `gemini-3-flash-preview` | ✅ запасні |

Ліміти безкоштовного тарифу **добові й окремі для кожної моделі**. Тому `call_gemini` іде по
`GEMINI_MODELS` (env, за замовчуванням `flash-lite-latest → 3.1-flash-lite → 3-flash-preview →
flash-latest`): 429 з `…PerDay…` → модель вимикається до кінця доби, одразу наступна; 503/хвилинний
429 → пауза 5/10 с і повтор. Деталі квоти — у тілі 429 (`quotaId`, `quotaValue`, `retryDelay`).

**Пастка перемикача:** `LLM_COOLDOWN` (5 хв) після першого 503 вимикав канал — замір показав
30/30 «збоїв», хоча відмова була одна. Для заміру — `LLM_COOLDOWN=0`.

### Для чого Gemini, а для чого — ні
- ✅ **штучна робота**: відповіді покупцям (чернетки для бота-помічника), опис окремого товару,
  переклад, розбір характеристик, короткі тексти для десятків карток;
- ⚠️ **масова генерація тисяч карток** — невідомо, скільки дає flash-lite на добу; перед прогоном
  на >200 карток — пробний прогін і читати `logs/llm_router.jsonl` (які моделі, скільки 429);
- ❌ висновки, гроші, живі замовлення — платний канал (правило §5 нижче лишається).

### Якість тексту — що цифри заміру НЕ ловлять
1. **Заборону чисел модель обходить словами**: «об'ємом п'ятдесят сім мілілітрів». Перевірка
   `NUM_UNIT` у заміру цього не бачить. Промпт має **дозволяти числа з даних**, а забороняти
   лише числа, яких у даних нема.
2. **Дерев'яний стиль** («представлений в інтернет-магазині») при суворому промпті — давати зразок
   бажаного тексту й перелік заборонених штампів.
3. Правило SKILL-23 незмінне: модель — не джерело фактів. Читати 5–10 результатів очима.

## 1. Що встановлено

**OmniRoute** — локальний шлюз до 358 провайдерів ШІ, з них 150+ мають
безкоштовні тарифи. API сумісне з OpenAI.

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data \
  -e OMNIROUTE_MEMORY_MB=2048 --memory 4g diegosouzapw/omniroute:latest
```

- **Тільки ноутбук.** Сервер має 3 ГБ пам'яті, для коду-агентів шлюзу треба
  8–12 ГБ. Панель і легкі запити — 1–2 ГБ.
- **npm-установка не підходить:** потрібен Node ≥ 22, на ноутбуці 20. Тому Docker.
- **Порт лише 127.0.0.1.** Назовні не виставляти: у шлюзі лежать ключі.
- Образ 4,14 ГБ, версія 3.8.51 (16.09.2026).

### Перевірка безпеки перед установкою (робилась, повторити після оновлень)

| Що перевіряли | Результат |
|---|---|
| телеметрія, відправлення назовні | немає; «аналітика» — локальна БД з терміном зберігання |
| власний домен `radar.omniroute.online` | лише **завантаження** підписаного каталогу, за згодою, з перевіркою підпису |
| інші домени в коді | самі провайдери (OpenAI, Anthropic, Google, OpenRouter…) |
| ключі | у локальній базі контейнера |

Межа перевірки чесна: дивились мережу й поводження з ключами, а не всі
14,5 тис. файлів. Це стороннє ПЗ, яке швидко змінюється.

### Що лишилось зробити власнику

Пароль панелі. Контейнер стартував без `INITIAL_PASSWORD`, тож онбординг
проходиться у браузері на `http://localhost:20128`. Без пароля працює
безкоштовний канал без ключа (саме він нам і потрібен), але каталог моделей,
залишки безкоштовних тарифів і додавання своїх ключів — за паролем.

## 2. Механізм перемикання

`shared/utils/llm_router.py`, ланцюжок за замовчуванням **omniroute → ollama**.

```python
from shared.utils.llm_router import ask
r = ask('Переклади українською: …', task='text')
r['text'], r['channel'], r['model'], r['ms']
```

```bash
venv/bin/python shared/utils/llm_router.py --selftest   # які канали живі СЬОГОДНІ
venv/bin/python shared/utils/llm_router.py --stats      # хто насправді відповідав
```

Правила, закладені в код:

- **Anthropic у ланцюжку немає.** Платний канал — рішення власника, а не
  запасний варіант за замовчуванням.
- **Впалий канал вимикається на 5 хв** (`LLM_COOLDOWN`), щоб кожен наступний
  запит не чекав того самого таймауту.
- **Коротка відповідь = збій каналу**, а не результат (`min_len`). У NVIDIA NIM
  напівживі моделі виглядали саме так.
- **Кожна відповідь у журнал** `logs/llm_router.jsonl`: канал, модель, час,
  довжина. Питання «звідки взялася ця відповідь» має відповідь у файлі.

Налаштування через `.env` (за потреби): `OMNIROUTE_URL`, `OMNIROUTE_MODEL`
(за замовчуванням `auto` — шлюз обирає сам), `LLM_CHAIN`, `LLM_COOLDOWN`.

## 3. Що показав замір (16.09.2026)

`tools/llm_channel_bench.py`: 30 справжніх товарів постачальника, однакове
завдання «2 речення опису строго за даними», рахуються **дефекти, які можна
порахувати**, а не «краса тексту».

| | omniroute (безкоштовний) | ollama (llama3.2:3b) |
|---|---|---|
| відповіли | 30/30 | 30/30 |
| вигадані числа | 0 | 0 |
| мішанина мов («Гель-lubрикант») | **0** | **11** |
| російські маркери | 0 | 0 |
| медіана часу | ~11 с | ~1 с |
| довжина опису | ~270 символів | ~190 |

**Висновки.**

1. **Українська в Ollama ламається** — латиниця всередині кириличних слів у
   третині описів. Це саме те, що потім ловить модератор.
2. **Вигаданих чисел не було в жодного каналу**, коли в завданні прямо
   написано «заборонено додавати числа, яких немає у даних». Тобто вада
   Ollama з пам'яті `ollama-ukrainian-models` керується формулюванням
   завдання, а не лише вибором моделі.
3. **Шлюз у 10 разів повільніший.** Для 5 тисяч карток це 15 годин проти
   1,5 — планувати як нічну роботу, не інтерактивну.

## 4. Коли який канал

| Задача | Канал | Чому |
|---|---|---|
| описи, переклади, ключові слова для карток | **omniroute** | мова не ламається, безкоштовно |
| масові прогони на тисячах карток | omniroute вночі, Ollama якщо треба швидко | різниця в часі 10× |
| чернетка, службовий текст, де мова не критична | ollama | миттєво, без мережі |
| заміри, висновки, рішення, гроші, живі замовлення | **платний канал** | тут ціна помилки вища за вартість токенів |

**Незмінне правило:** жоден канал не є джерелом фактів про товар (SKILL-23).
Числа, склад, розміри — лише з даних постачальника чи довідника майданчика.

## 5. Чого НЕ робити

- **Не вірити каталогу провайдерів.** У NVIDIA NIM з 82 моделей працювала
  одна (`nvidia-nim-usage`). Перед прогоном — `--selftest`, і дивитись на
  відповідь, а не на список.
- **Не виставляти порт 20128 назовні** й не класти в шлюз ключі
  маркетплейсів: йому потрібні лише ключі LLM-провайдерів.
- **Не переносити на сервер** — не вистачить пам'яті.
- **Не вважати «~89 % економії токенів» з опису проєкту виміряним.** Ми цього
  не перевіряли.
- **Не перемикати на безкоштовні моделі роботу з висновками й грошима.**

## 7. Делегування задач безкоштовному каналу (перевірено 16.09.2026)

`tools/llm_delegate.py` — задача маркдауном → безкоштовна модель пише файл →
**тести замовника** приймають роботу → звіт → перевіряє основна модель.

```bash
venv/bin/python tools/llm_delegate.py \
  --task docs/tasks/TASK-01-voice-intents.md \
  --target tg_dispatcher/ai_brain/intents.py \
  --tests tests/test_voice_intents.py --rounds 4
```

### Що показав перший прогін

Задача: розбір голосових команд Telegram (9 намірів, 5 параметрів, 42 тести).

| | результат |
|---|---|
| код з першої спроби | 198 рядків за 95 с |
| тести замовника | **38 із 42** |
| що не склалось | словоформи: «заказы», «розетки/розетці» |
| що знайшла основна модель **очима**, а не тестами | `raw` повертався обрізаним, хоча за ТЗ — незмінним |
| доробка основної моделі | 4 правки, ~20 рядків |

**Висновок: модель робить ~90 % добре описаної задачі.** Останні 10 % —
словоформи української й дрібні розбіжності з ТЗ — лишаються людині або
основній моделі.

### Умови, без яких це не працює

1. **Тести пишуться ДО постановки** і виконавцем не редагуються. Без них
   «готово» означає «схоже на правду».
2. **ТЗ із точним інтерфейсом** — назви ключів, перелік значень, приклади
   фраз. Загальне формулювання дає загальний код.
3. **Один файл за раз.** Правки в наявних файлах моделі не давати.
4. **Приймання — це читання коду, а не лише зелені тести.** Дефект з `raw`
   тести пропустили, бо в них не було пробілів по краях.

### Пастки запускача, на яких я вже наступив

| Пастка | Наслідок | Як виправлено |
|---|---|---|
| `pytest.importorskip` у тестах | модуля немає → тести **пропущені**, ворота зелені | відсутність модуля = провал |
| pytest не стояв у venv | ворота не запускались зовсім | `venv/bin/pip install pytest` |
| запобіжник каналу (5 хв) | блокував повторні спроби всередині кола | скидається перед кожною спробою |
| гірший результат затирав кращий | 38/42 замінилось на 37/42 | зберігається найкращий файл |
| повторний запит удвічі більший за перший | шлюз віддавав 400 | у повтор іде лише перелік провалених тестів |
| мережевий збій | коло втрачалось | 3 спроби з паузою 30/60/90 с |

**Безкоштовний канал нестабільний:** з чотирьох великих запитів два
завершились помилкою шлюзу. Для довгої генерації це нормально; тому
повтори обов'язкові, а робота ділиться на дрібні задачі.
