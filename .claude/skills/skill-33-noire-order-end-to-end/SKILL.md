## Післяплата: поточна поведінка (перевірено 15.09)

> **Власник 15.09: «післяплата моя робота і не зважай на це поки».** Звірка показує її лише як ℹ️, не як відхилення. Скрипт ТТН не змінюємо.

| Оплата в Rozetka | Що робить `np_create_ttn.py` | Післяплата в ТТН |
|---|---|---|
| Оплачено (`paid`) | ТТН без післяплати, друкує наклейку | не потрібна ✅ |
| При отриманні (`cash`/`cod`) | пробує післяплату на картку (`PaymentCard`) → НП: 20000201794 «тимчасово заблокована» → **створює без післяплати**, наклейку не друкує, у Telegram «додайте післяплату N грн» | **немає** ⚠️ |

**Отже, зараз ТТН для замовлень з оплатою при отриманні створюються БЕЗ післяплати.** Так вирішив власник 13.09: картку через API поставити не можна.

**Пастка кроку 10.** Для CRM потрібна наклейка 100×100, а друк блокує зміну ТТН через API («Document is already printed»). Для #906078985 наклейку надруковано з післяплатою 0 грн, 1298 грн не додано (власник: «не звертай увагу на післяплату», 15.09). Чи можна додати післяплату в кабінеті НП після друку, не перевірено.

**Перевірена альтернатива.** Післяплату **без картки** API приймає: 13.09 тестова ТТН 20451535093446 створилась із сумою 100 грн без картки, потім її видалено. Така ТТН одразу має післяплату, і кроки 6–10 її не втрачають. Куди надходять гроші без картки і чи можна перевести їх на картку, треба уточнити. Скрипт так **не працює**, поки власник не вирішить.

## Кінцева звірка: `tools/noire_order_verify.py`

Запускати **після всіх операцій**. Лише читає і звіряє три джерела між собою, а не з повідомленнями скриптів:

| Джерело | Що звіряє |
|---|---|
| Rozetka | статус ≥ 61, ТТН є, склад, сума, тип оплати |
| Нова Пошта | ТТН в акаунті; № замовлення в ТТН; відділення і телефон = Rozetka; оголошена = сума; післяплата (оплачено → 0; при отриманні → = сума, 0 → ⚠️); стан |
| CRM | замовлення з цією ТТН; ТТН прикріплена файлом; позиції = Rozetka; документ і сума у валюті; **оплата постачальнику** (`paid`); «оплачено понад 24 год, а НП ще не відвантажено» → ⚠️ |
| Журнал | є сума до сплати |

Позначки: ✅ збігається · ⚠️ відоме відхилення · ❌ розбіжність. Код виходу 1, якщо є ❌. З `--tg` у Telegram ідуть лише ⚠️ і ❌.

Перший прогін 15.09:
- **#906078985 / CRM 1393615:** ❌ 0, ⚠️ 1, післяплата 0 грн.
- **#905931436 / CRM 1392013:** ❌ 0, ⚠️ 1: у CRM «не оплачено 27,95 €», посилка з 14.09 не відвантажена. Власник з'ясував: постачальник не відправив через атаки, оплату зроблено, відвантаження перевіряють. Контролювати **не потрібно** (власник, 15.09).

## Чому шлях поки не запускається автоматично

1. **Пройдено один раз.** Одне замовлення — це один зразок. Не перевірені:
   - товар, якого ще немає в кошику;
   - кілька позицій в одному замовленні;
   - передоплата, яку ще не отримали;
   - поштомат;
   - два замовлення одночасно, коли кошик спільний.
2. **Дії незворотні і з грошима.** ТТН, оформлене замовлення в CRM, списання з передоплати. Помилку в автоматичному режимі видно лише постфактум.
3. **Не вирішено питання з післяплатою.** Автоматичний режим зараз створював би ТТН без неї.
4. **Правило проєкту:** зміна поведінки агентів замовлень — лише з дозволу власника (SKILL-22).

**Умова ввімкнення (запропоновано власнику 15.09).** Кожне нове замовлення NOIRE проходимо разом:
- кроки 6–13 виконую я, власник дивиться;
- наприкінці запускаю `noire_order_verify.py`.

Коли **3 замовлення поспіль** матимуть ❌ 0 без жодного ручного виправлення, і серед них буде хоча б одне з передоплатою і одне з кількома позиціями, пропонуємо власнику автоматичний режим. Автоматично вмикається лише кроки 6–10. Оплату й далі робить власник.

## Де що дивитись

- Rozetka: `get_order_details()`, ТТН через `_ttn_of()`.
- Лог агента: `/tmp/rozetka_order_agent.log`. Стан у БД: `rozetka_processed_orders`. NOIRE після підтвердження має стан `accepted`, і далі агент його не чіпає. Замовлення в статусі 61 з NOIRE-товарами до Carvol не потрапляють: гілка NOIRE завершується раніше.
- НП: `InternetDocument.getDocumentList` за датою → `IntDocNumber`, `BackwardDeliveryMoney`, `Printed`, `InfoRegClientBarcodes`.
- CRM: `GET /uk/inner/checkout/<id>` з `x-auth-token`.
- Пошта: Gmail `from:info@smtm.com.ua`, тема «ID <id> - new order on new.smtm.com.ua».

## Що ще вручну

- Крок 6 запускається вручну. Автоматичний запуск після кроку 4 — лише з дозволу власника.
- Кроки 8–10 поки проходять по одному замовленню з перевіркою. «Оформити замовлення» без прямої вказівки власника не натискаємо.
- Крок 13 (оплата постачальнику) робить **власник вручну, без нагадувань**. Автоматизувати не будемо: «не знаю чи безпечно це автоматизовувати» (15.09).
- ТТН: опис — коротка назва товару, № замовлення Rozetka в ТТН лишаємо (рішення 15.09).
