# SKILL-31. Пошук по Prom: видимість конкретної картки

Відпрацьовано 12.09.2026. Інструменти: `tools/prom_search.py` (замір
видимості), `tools/prom_keywords_probe.py` (чи індексуються ключі),
`tools/prom_same_product_probe.py` (гіпотеза склеювання).

---

## 1. Що працює

`https://prom.ua/ua/search?search_term=<запит>&page=N` — звичайний HTML,
браузер не потрібен (заголовки: браузерний `User-Agent`,
`Accept-Language: uk-UA`). У відкриваючому тезі кожного блоку товару:

```
data-qaid="product_block" data-product-id="3152112459" data-company-id="4053918"
```

* `data-product-id` — **prom_id** картки → звірка з `prom_product_state.prom_id`;
* `data-company-id` — магазин; **наш — 4053918** (як `cs4053918.prom.ua`);
* усередині блоку: `product_name`, `company_name`, `product_price`.

## 2. Пастки розмітки (кожна перевірена)

* `&page=N` працює; **`&p=N` ігнорується** й повертає першу сторінку;
* `data-qa-advtoken` стоїть на **кожному** блоці — це НЕ ознака реклами;
* `data-position-qaid` починається з 1 на кожній сторінці — позиція наскрізна, рахувати самим;
* та сама картка буває у видачі двічі (SO5178: 1-ша і 11-та) — перше входження;
* **видача нестабільна між запитами**: 3 з 10 карток за тим самим запитом
  то є, то немає (12.09). Одиночний прогін — не факт; для висновку про
  картку — щонайменше два запити.

## 3. Чому звірка лише за prom_id

Старі способи давали хибні «знайдено»: за іменем продавця — у видачі
траплялась ІНША наша картка (SX4628, SO5943, 08.09); за схожістю назви —
те саме для варіантів кольору. prom_id однозначний.

## 4. Позитивний контроль

`SO5178`, prom_id 3152112459, за точною назвою — 1-ша позиція. Інструмент
перевіряє його ДО і ПІСЛЯ прогону й зупиняється, якщо не знайшов.

## 5. Що пошук Prom враховує — заміри 12.09 (за довгим запитом = повна назва)

| Додали до повної назви слово, яке є лише в… | Картка лишилась у видачі |
|---|---|
| `keywords_ua` | **0 з 10** (3 — «м'який» пошук, не розрізняють) |
| видимому тексті опису (стабільно з 11.08) | **0 з 10** |
| характеристиках (з 07.09) | 1 з 5 |
| ніде (негативний контроль «тракторний») | 0 з 10 |

Тобто за довгим запитом збіг іде лише по назві; слова з ключів і опису
поводяться як відсутні. **Застереження:** це режим довгого запиту; для
коротких запитів не перевірено (короткий «бренд + модель» не показує наших
карток навіть проіндексованих — там перемагають інші продавці, тож контролю
немає).

**Пастка вимірювача, на яку наступив:** слово з опису треба брати з
ВИДИМОГО тексту — перша версія взяла `justify` із `style="text-align:justify"`.

## 6. Замір видимості 12.09 — 150 випадкових карток

```
знайдено за точною назвою    16/150 = 10.7 %  (95 % інтервал 6.7–16.6 %)
усі 16 — на 1-й сторінці; 134 не знайдено й на 2–3 сторінках
на місці незнайдених ІНШОЇ нашої картки не було жодного разу
```

Двоїстий розподіл: картка або в індексі й нагорі, або відсутня зовсім.
Ознаки тексту (дублікат опису, к-сть ключів, вік, фото) у знайдених і
незнайдених однакові. Єдина стійка різниця — довжина назви: разом з 08.09
<70 симв. 14.5 % проти >95 симв. 4.2 %, Фішер p = 0.065.

## 7. Запуск

```
python3 tools/prom_search.py --query "вібратор lelo"          # сира видача
python3 tools/prom_search.py --sample 150 --out docs/…tsv     # замір
python3 tools/prom_search.py --skus SO5178,SO5463
python3 tools/prom_keywords_probe.py --from docs/prom_visibility_20260912.tsv
```

Потрібен знімок `data/prom/prom_ids.json` (external_id → prom_id з
`prom_product_state`) і опублікований фід (завантажується сам, кеш 12 год).
