## SKILL-11 — Prom API

Коли треба **дізнатись фактичний стан карток**, а не те, що ми відправили.

Головне: документація бреше в трьох місцях. Категорію через API змінити
**неможливо** (перевірені всі чотири назви поля). `group` ≠ `category`:
перше — папка магазину, друге — категорія маркетплейсу. HTTP 200 не означає
запис — читати `processed_ids`.

Токени на ноутбуці й сервері різні; перевіряти саме ту копію `.env`, з якої
піде виклик.

## SKILL-13 — офіційні правила SEO Prom

Коли пишеш назви, keywords, описи, характеристики для Prom.

Формула назви, ліміт **110 символів** (не 130), видима зона 70, логіка
keywords (словосполучення, дистанція до 5 слів), роздільник `|` для
множинних значень, `<group_id>` як єдиний механізм різновидів.

**SKILL-13.13 — таблиця звірки.** Вихідний файл `пром сео.txt` виявився
компіляцією з вигаданими числами. Дев'ять тверджень спростовано.

## Технічні уроки без номера

Дорого здобуті факти, які не мають окремого файлу, але коштували найбільше.

### Назви характеристик не збігаються між системами

Наші назви ≠ назви довідника майданчика. `Довжина (мм)` → `Довжина`,
`Тип живлення` → `Живлення`, `Вид` → `Тип мастурбатора`. Без словника
трансляції дані є, але у фільтри не доходять: у Prom так губилось
**29 831 значення**.

Три словники в `noire_prom_generator.py`: `PARAM_ALIAS` (назви),
`FEATURE_MAP` (булеві → «Особливості»), `EFFECT_MAP` (булеві →
«Додатковий ефект» — це **інший** перелік, значення одного в іншому
не приймається).

Окремо: **«Об`єм» у Prom пишеться через зворотний апостроф.** Через один
символ характеристика мовчки не знаходилась ніде.

### Одиниці виміру залежать від категорії

У Prom `Довжина` буває і в мм (ліміт 2000), і в см (ліміт 25) — у різних
категоріях по-різному. Конвертувати треба за `measure_unit` категорії,
а результат звіряти з `min_value`/`max_value`: вихід за межі означає
помилку в даних постачальника («Діаметр 320 мм» на вібраторі).

### `<keywords_ua>` існує

Був період, коли я вирішив, що тега немає, і побоявся невідомого тега.
**Помилка.** Тег задокументований у специфікації YML. Наслідок помилки:
3806 фраз ішли в російське поле, українська аудиторія не бачила жодної.

Мораль ширша: **дочитувати специфікацію до кінця**, а не зупинятись на
першому «не знайшов».

### `<dimensions>` існує і потрібен

```xml
<dimensions><weight unit="kg">…</weight><width unit="cm">…</width>
  <height unit="cm">…</height><length unit="cm">…</length></dimensions>
```

Порожні габарити змушують майданчик брати середні по категорії, що може
заблокувати доставку поштоматом. Джерело оцінок — `epicentr_default_dimensions`.

### MD5 + SHA1 як обовʼязковий доказ деплою

Правило записане в `CLAUDE.md` окремим розділом. «Готово» вимагає трьох
перевірок: розгорнуто на сервері публікації, MD5 генератора збігається,
опублікований URL звірено з локальним файлом.

**Чому:** 10.08.2026 менеджеру Rozetka написали «усі зауваження виправили»,
а за посиланням лежав невиправлений файл — локально все було зроблено, на
сервері стояв старий генератор. Дата в шапці оновлювалась щогодини й
маскувала проблему майже добу. Для хешу фіду брати `git blob sha1` через
GitHub API: `raw.githubusercontent.com` кешує 300 секунд.

### Джерела «офіційної документації» треба звіряти

Двічі отримували компіляції, видані за офіційні документи, з правдоподібними
вигаданими числами. Обидва рази звірка з першоджерелом знаходила
спростування. Перед внесенням у генератор — перевіряти.
