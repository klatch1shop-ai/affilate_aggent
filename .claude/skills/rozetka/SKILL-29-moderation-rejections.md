# SKILL-29. Розетка: чому картки не публікуються

Розібрано 05.09.2026 на 1031 заблокованій картці. До того ми два дні шукали
причину не там: припускали фото, а фото — це лише третина.

---

## Де взяти причини

**В API їх немає.** Перевірено все, що є:

| метод | що дає |
|---|---|
| `GET /items/counts` | активні / неактивні / модерація — лише числа |
| `GET /items/{id}` | `moderation_status` у всіх **0**, `details` = `null` |
| `GET /items/statuses-moderation` | повертає **порожній масив** |
| `GET /items/search?item_active=0` | статуси, без причин |
| `GET /items/create-export-file` + `download-export-file` | 12391 рядок, **10 колонок, причин немає** |
| `GET /reports/search` | місячні **фінансові** звіти, не модерація |
| `/item-comments/*` | відгуки **покупців**, не модератора |

Спроби вгадати ендпоінт (`/items/rejected`, `/moderation/search`,
`/exports/search`, ще вісім варіантів) — усі `5404 not_found`.

**Єдиний шлях — кабінет вручну:** Товари → Неактивні → вкладка «Приховані
модератором» → кнопка **Експорт** → файл забирається в **«Мої Завантаження»**.
Дає XLSX на **27 колонок**, серед них `Причина блокування`, `Коментар
менеджера`, `Дата відхилення`.

Параметри в `create-export-file` (`type`, `uploader_status`, `moderation`)
**ігноруються** — файл завжди однаковий.

## Розшифровка статусів

Ніде не задокументована; здобута зіставленням API з експортом:

```
uploader_status = 2  →  «Не пройшов модерацію»     (1022 картки)
uploader_status = 4  →  «Активний» або «Прихований»
Sell-статус «Скрытый» = 1031                        (усі заблоковані)
```

Ключове: **неактивна картка ≠ відхилена**. З 4654 неактивних **3615 просто
немає в наявності**. Реальний клас проблем — `uploader_status=2`, і серед них
712 у наявності.

## Справжній розподіл причин

```
647  (62 %)  Відсутній параметр для групування
372  (36 %)  Фото  (не відповідає вимогам 214, не відповідає товару 130,
                    відсутнє 18, сторонній ресурс 3, низька якість 2)
  9          Заборонений контент
  3          Некоректна характеристика
```

> **Головна причина — не фото, а групування.** Два дні я будував детектор
> зображень, тоді як 62 % проблеми лежало в структурі фіду.

## Що каже модератор дослівно

Коментарі повторюються майже слово в слово на 879 картках:

```
386  перше фото — вид товару вживу в повному розмірі спереду,
     зірочки і соски заборонені + розмір у назві
 79  ...зірочки заборонені + розмір у назві і характеристиці
 76  ...+ вказати розмір
 37  зірочки на фото заборонені
 20  В описі вказано що в комплект входить перехідна рамка, на фото вона відсутня
  9  Написи на фото мають бути українською або дублюватись
```

Плюс із картки в кабінеті: **«розмір у назві і х-ках має бути однаковим»**.

Звідси чотири конкретні вимоги, і жодна не збігається з тим, що я перевіряв:

1. **Товар має бути НА МОДЕЛІ**, спереду, цілком. Для білизни людина в кадрі —
   не порушення, а вимога. Правило «людина = брак», виведене на мастурбаторах,
   тут інвертується.
2. **Цензурні зірочки заборонені.** Це головна причина відмов по фото, і
   класичний комп'ютерний зір її не бачить — потрібна візуальна модель.
3. **Розмір має бути і в назві, і в характеристиці, однаковий.**
4. **Опис не має обіцяти того, чого немає на фото.**

Повідомлення також називає **які саме поля міняти**: «Фото» або «Назва, Назва
Українською, Параметри». Це готовий машинний сигнал, якщо файл розбирати.

## Перевірка гіпотези «справа у фото» — спростована

Порівняння 15 опублікованих карток білизни з 15 заблокованими **тієї самої
категорії**:

| ознака | опубліковані | заблоковані |
|---|---|---|
| модель у кадрі (точок скелета) | **14** | **8** |
| товар у кадрі | 61 % | 50 % |
| текст на фото | 0 | 0 |

Опубліковані мають моделей **частіше**. Серед заблокованих є картки з
бездоганним фото — товар на 95 % кадру, 1800×1800 — і вони все одно приховані.

## Порядок робіт, який із цього випливає

1. **Параметр групування — 647 карток.** Одна правка генератора: розміри одного
   товару мають ділити спільний параметр. Довідка:
   `sellerhelp.rozetka.com.ua/p188-product-grouping.html`. Групують за
   розміром, кольором, обʼємом; правила залежать від категорії й видно їх у
   кабінеті: Управління товарами → Правила групування.
2. **Розмір у назві та характеристиці, однаковий** — той самий прохід.
3. **Фото — 372 картки**, і лише тут потрібна візуальна модель, бо шукати треба
   цензурні зірочки й відповідність фото товару.

## Побічна знахідка

Серед заблокованих 38 «Перехідних рамок», 7 «Головних пристроїв» і 2
«Аксесуари для автозвуку» — товари **Carvol у фіді NOIRE**. Двадцять коментарів
модератора про «перехідну рамку, якої немає на фото» стосуються саме їх.
Це окремий дефект: змішування двох постачальників в одному фіді.
